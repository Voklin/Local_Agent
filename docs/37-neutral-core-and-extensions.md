# Neutral: ядро, расширения и проверка действий

## Сравнение с Hermes

25 октября 2026 изучены официальные исходники
[Hermes Agent](https://github.com/NousResearch/hermes-agent):
[реестр инструментов](https://github.com/NousResearch/hermes-agent/blob/main/tools/registry.py)
и [работа с навыками](https://github.com/NousResearch/hermes-agent/blob/main/tools/skills_tool.py).
Ниже перечислены принципы, реализованные в Neutral. Сходство принципов не означает
совместимость всех пакетов двух продуктов.

| Область | Исходное состояние Neutral | Изменение |
| --- | --- | --- |
| Агентный цикл | Потоки, tools, JSON-адаптер, история, checkpoints, diff уже существовали | Сохранены в одном движке; удалена надстройка четырёх моделей |
| Реестр возможностей | Отдельные списки файловых, голосовых и desktop tools | ExtensionService объединяет их и применяет переключатели до запроса и выполнения |
| Навыки | Выбор краткого описания по словам | Каталог метаданных и явное чтение полной инструкции по необходимости |
| Опыт агента | Автоматической записи не было | create_skill создаёт выключенный черновик; пользователь просматривает и включает |
| MCP | Объекты описания без транспорта | Настоящие stdio и Streamable HTTP: initialize/list_tools/call_tool через SDK |
| Повторы | Шесть одинаковых соседних вызовов | Дополнительно обнаруживаются одинаковые результаты в окне, включая чередование A/B |
| Ошибки tools | Ошибка обработчика могла оборвать задачу | Ограниченный результат ошибки возвращается модели; работают общие лимиты |
| Проверка кода | Просмотр файлов | Опциональная команда теста/сборки с отдельным подтверждением и результатом процесса |
| Соединение | Только совместимый Chat Completions | Отдельный Responses-адаптер и именованные профили |

Это не заявление о полном паритете с Hermes, Claude Code или другими агентами.
В Neutral нет произвольной установки Python-кода плагина, магазина расширений,
удалённого облачного выполнения или автоматической выдачи новых прав навыком.

## Путь одной задачи

`TaskService.start` проверяет режим, модель и выбранный проект. Затем получает
`ExtensionService.snapshot`: определения tools, разрешённые имена, включённые
навыки и разрешённые MCP-вызовы. Снимок принадлежит одному запуску. Изменения
настроек применяются к следующей задаче; изменение настроек во время работы
блокируется сервисом.

Движок получает определения и диспетчер. Модель видит только выбранные инструменты.
На ответе её вызов снова проверяется по определениям, затем диспетчер проверяет
снимок. `write_file` по-прежнему обрабатывается внутри движка через существующий
preview/revision/diff протокол. Расширения не обходят эту проверку.

Полная история остаётся канонической. ContextManager строит ограниченное рабочее
представление для конкретного запроса. Имеющееся умное сжатие и память проекта
не заменены новым реестром. В prompt добавляются пользовательские инструкции
проекта и каталог включённых навыков; тела навыков поступают только после чтения.

## Наборы, инструменты и плагины

**Настройки → Расширения → Плагины** показывает встроенные наборы: файлы, обычные
задачи ассистента, компьютер, навыки и команды. **Инструменты** позволяет выключить
отдельное действие. Выключенный набор скрывает все свои инструменты независимо
от индивидуального переключателя. Desktop также требует прежнего разрешения
в разделе компьютера. Команды проекта по умолчанию выключены.

Внешний плагин — декларативный JSON-пакет версии 1. Например:

```json
{
  "version": 1,
  "name": "Проверка интерфейса",
  "description": "Повторяемая ручная проверка",
  "tools": [],
  "skills": [{
    "title": "Проверка формы",
    "summary": "Когда менялась форма ввода",
    "content": "Проверь пустой ввод, неверные данные, успешное сохранение и сообщение пользователю."
  }],
  "servers": []
}
```

Импорт выполняется системным выбором файла, JSON ограничен 200 КБ. Серверы
проверяются до записи; ID должны быть уникальными. Пакет появляется выключенным.
Включение пакета включает перечисленные навыки/серверы/встроенные инструменты.
Токены не импортируются. Пакет не может зарегистрировать произвольную Python
функцию. Если нужен внешний исполнитель, добавляется явно настроенный MCP сервер.

Максимум: 40 пакетов, 20 серверов, 200 пользовательских навыков. Эти пределы
предотвращают бесконтрольный рост состояния и prompt. Они не являются лимитами
подключённой модели или лицензии пользователя.

## Жизненный цикл навыка

1. `skills_list` возвращает метаданные включённых инструкций.
2. `skill_view(id)` читает выбранную полную инструкцию.
3. Модель применяет инструкцию с уже имеющимися правами и инструментами.
4. После сложной успешно проверенной работы модель может вызвать `create_skill`.
5. Создаётся файл `extensions/skills/user_<uuid>.json`, статус — черновик.
6. В интерфейсе видно «Предложен агентом · ожидает просмотра». Пользователь может
   прочитать, поправить, включить или удалить навык.

Переключатель **Сохранять полезный опыт** убирает `create_skill` из доступных
инструментов. Это возможность и инструкция модели, а не отдельный фоновый
процесс, который гарантированно учится на каждом сообщении. Качество создаваемых
инструкций зависит от модели; секреты и одноразовые данные сохранять запрещено
инструкцией, а содержимое требует пользовательского просмотра.

Встроенные SKILL.md поставляются с приложением. Их можно прочитать и скопировать
в собственный навык; перезапись исходного встроенного файла из интерфейса запрещена.
Собственные навыки редактируются в своём каталоге вне проекта. Создание навыка
не исполняет команды, не устанавливает зависимости и не меняет настройки MCP.

## MCP

Используется официальный Python SDK `mcp==2.3.0`, API проверен по
[клиентской документации](https://py.sdk.modelcontextprotocol.io/client/)
и [транспортам](https://py.sdk.modelcontextprotocol.io/client/transports/).

Для stdio задайте название, короткий ID, программу и аргументы, каждый с новой
строки. Для HTTP — адрес Streamable HTTP и, если требуется, Bearer-токен.
Кнопка **Проверить** действительно подключается, получает инструменты и сохраняет
их схемы. После этого сервер можно включить. Модель не редактирует эти настройки.

`MCPClient.operation` открывает транспорт только на время discovery или одного
вызова. Контекст SDK принадлежит одной coroutine и закрывается в ней же. Это
проще для отмены и не оставляет постоянные серверы приложения, но локальный
stdio-процесс запускается заново на каждом действии. Сервер должен быть пригоден
для такого режима; постоянные сессии и OAuth flow пока не реализованы.

Имена tools в основном агенте получают префикс сервера и хеш исходного имени,
чтобы разные серверы не конфликтовали. Аргументы проверяются по JSON Schema.
У discovery максимум 5 страниц/100 инструментов, у схемы 30 КБ. Результаты
текстовые и ограничены; изображения/аудио возвращаются как метаданные без
неограниченного base64. Ответ сервера считается внешними данными, а не источником
разрешения читать новые папки или менять настройки.

По умолчанию каждый вызов показывает отдельное подтверждение: сервер/инструмент
и JSON аргументы. Пользователь может разрешить серверу действия без этой паузы
в его настройках. Это самостоятельное разрешение, поэтому режим применения
всех файловых diff не распространяется на MCP. Отклонение возвращается модели
как ошибка вызова. Стоп прерывает ожидание подтверждения и активное соединение.

Тайм-аут сервера ограничен 5–120 секундами. Диагностика stdio записывается
в `extensions/logs/<id>.log`; при следующем подключении большой прежний журнал
очищается. Токен остаётся в памяти, не попадает в JSON реестра; смена адреса
сбрасывает прежний токен и обнаруженные схемы.

## Команды теста и сборки

Включите **Проверки и команды проекта** в расширениях. Инструмент
`run_project_command` доступен только основной модели в IDE с выбранной папкой.
Он принимает программу, массив аргументов, относительную рабочую папку и тайм-аут.
Перед запуском всегда показывается отдельное подтверждение. Рабочая папка
должна находиться внутри корня, включая разрешение symlink/junction.

Node доступен через встроенный в Electron runtime. Прочие среды разработки
должны быть установлены; отсутствие программы возвращает понятную ошибку.
Нет конкатенации пользовательского текста в shell-строку. Batch/PowerShell
файлы и shell-интерпретаторы не принимаются; npm CLI при необходимости запускается
через node с явным путём к `npm-cli.js` установленного npm.

Процесс получает ограниченный набор стандартных переменных среды без API-ключей
приложения. В Windows `ProcessJob` завершает дочерние процессы при закрытии job.
Время — до 120 секунд; вывод — до 64 КБ с признаком усечения. В результат входят
`ok`, `exit_code`, `output`, время и причина отмены/тайм-аута. Ошибка теста с
ненулевым кодом не становится успешной проверкой.

Рабочая папка не является изоляцией ОС. Подтверждённый код запускается с правами
пользователя и может делать то, что доступно этому пользователю. Поэтому набор
выключен по умолчанию, а само разрешение на конкретную программу запрашивается
отдельно от diff. Не включайте его для недоверенного проекта без просмотра команды.

## Ограничение повторов и ошибок

`ProgressGuard` запоминает последние 16 отпечатков: имя, аргументы и результат.
Четыре одинаковых результата в этом окне приостанавливают задачу, даже когда
агент чередует два действия. Изменение результата создаёт другой отпечаток.
Сохраняется и прежний предел шести одинаковых соседних вызовов. История получает
структурно корректный tool result; контрольная точка остаётся для продолжения.

Журнал показывает имя инструмента, имена полей, успешность и размер результата;
полный код, аргументы и содержимое tool result больше не копируются в диагностический
журнал. Каноническая история самого разговора сохраняет результаты, необходимые
для продолжения. Это разные хранилища с разным назначением.

## Основные файлы и проверки

| Файл | Ответственность |
| --- | --- |
| agent/engine.py | Поток, цикл tools, checkpoint, diff, завершение и отмена |
| core/python/task_service.py | Один активный запуск, конфигурации, история, подтверждения |
| core/python/extension_service.py | Реестр, переключатели, навыки, пакеты и снимок возможностей |
| agent/mcp_client.py | Проверка сервера, SDK transport, discovery и вызов |
| agent/project_command.py | Запуск подтверждённого процесса и ограничение ресурсов |
| agent/progress_guard.py | Обнаружение отсутствия продвижения |
| agent/responses_adapter.py | Responses input/events и продолжение functions |
| apps/desktop/src/ExtensionsSettings.tsx | Управление всеми расширениями |

Существующий `agent/mcp.py` остаётся совместимой структурой старого runtime;
транспорт Electron реализован `agent/mcp_client.py`. Старый объект реестра не
означает подключённый сервер.

Тесты включают настоящий локальный stdio и Streamable HTTP сервер, проверку
схем, отказ подтверждения, отмену медленного вызова, выключение tools, черновики
навыков, JSON-пакеты, ограничение вывода команды и код возврата. Сквозной
`tests/electron/neutral-smoke.cjs` проходит через renderer → preload → main →
stdio → AgentEngine → MCP/процесс с изолированным пользовательским каталогом.

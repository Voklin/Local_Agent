# 18. Рабочий редактор IDE

## Путь пользователя

В IDE нажмите текстовый файл в проводнике. Каждый открытый файл получает вкладку; переключение не перечитывает его и не теряет локальные изменения. Точка около имени означает отличие черновика от прочитанного текста. Редактор показывает номера строк, строку/колонку, UTF-8 и стиль LF/CRLF. Перенос включается отдельной кнопкой; при переносе gutter скрыт, чтобы номера логических строк не расходились с визуальными.

Ctrl+F открывает поиск внутри файла с циклическим переходом, Ctrl+G — номер строки, Ctrl+Shift+R перечитывает файл, Ctrl+S получает diff. Сохранить может и кнопка панели. Ни одно нажатие Save не пишет сразу: сначала показан конкретный diff, затем «Применить и сохранить». Reject/Cancel оставляют черновик редактируемым.

Вкладки живут при переходах Chat/IDE/Ассистент: App не размонтирует EditorPanel, а меняет видимость рабочего main. Закрытие dirty-вкладки, смена проекта и закрытие окна требуют явного отказа от несохранённого текста. Default нативного диалога — Cancel. Отмена закрытия окна оставляет Core работающим. В 6.1 `before-quit` также проверяет dirty до начала cleanup, поэтому Cancel при `app.quit()` не завершает ядро.

При остановке Core локальные drafts не удаляются. Снова выбрав тот же проект, можно продолжить; Save по-прежнему проверит revision. Это хранение в памяти окна, а не crash-draft для ручного editor: аварийное завершение всего Electron может потерять ещё не сохранённый текст. Автоматической записи черновиков проекта на диск этот этап не добавляет.

## Две версии файла

Вкладка содержит `content` (редактируемый текст), `original` (последний прочитанный текст), `revision` (канонический относительный путь и SHA-256 исходных байтов) и newline-стиль. Dirty сравнивает content с original. Revision никогда не пересчитывается по новому draft на стороне UI: это маркер версии диска, относительно которой началось редактирование.

EditorService.read читает не больше 1 МБ, строго декодирует UTF-8 и отвергает NUL. Старый read_file preview мог показывать replacement characters для неизвестной кодировки; новый editor не позволяет случайно сохранить такой результат поверх оригинала. CRLF в UI представлен как LF, но полностью CRLF-файл сохраняет CRLF при записи. Смешанные окончания строк при сохранении нормализуются в LF; итог всегда виден в diff. BOM остаётся обычным символом текста, отдельный конвертер кодировок не добавлен.

## Контракт сохранения

| Шаг | API / RPC | Что проверяется |
| --- | --- | --- |
| Read | editorRead / editor_read | Root, существующий обычный файл, размер, UTF-8/NUL, byte hash |
| Preview | editorPreview / editor_preview | Задача агента idle; тот же byte revision на диске; новый текст в лимите |
| Approval | React editor-approval dialog | Пользователь видит только конкретное предложение, текст ещё не записан |
| Resolve | editorResolve / editor_resolve | Одноразовый proposal ID, тот же root и допустимое решение |
| Apply | существующий write_file | Повторная проверка полного preview snapshot, atomic temporary write/replace |

EditorService хранит только одно pending предложение в памяти Core: ID, root, canonical path, предложенный текст, snapshot. Не доверяет новому тексту из Resolve: этот RPC передаёт только ID и решение. Новое Preview, решение или смена проекта сбрасывают прежнее предложение. После restart старый ID не существует. Даже неудачный Apply потребляет предложение.

Если файл изменился после чтения, Preview возвращает FILE_CHANGED до диалога. Если изменение произошло после показа diff, write_file отказывает на Apply. В обоих случаях UI сохраняет draft и предлагает перечитать файл. Не появляющаяся кнопка «всё равно перезаписать» — сознательная граница этого этапа: пользователь может скопировать свой draft, перечитать актуальный файл и создать новое изменение.

Пока pending editor approval активен, backend не запускает задачу агента. Пока агент работает, ручные Preview/Resolve отклоняются через TaskService.idle. Чтение и локальное редактирование могут продолжаться. Если агент изменил открытую чистую вкладку, она перечитывается; dirty-вкладка получает предупреждение, но её текст не заменяется. Агент видит сохранённые файлы на диске, а не несохранённые textarea drafts.

Во время сохранения/диалога textarea заблокирована: новые набранные символы не могут быть затёрты результатом уже подготовленного предложения. При ошибке повторного чтения после успешной записи backend возвращает applied=True и warning; UI не выдаёт это за отменённую запись и сохраняет текст для проверки.

## Границы полномочий

Все пути проходят canonical_root/resolve_allowed_path, включая symlink/junction targets. Произвольная команда записи, shell или доступ вне project root в IPC не появились. Ручное изменение всё равно требует preview→decision→atomic write. Existing-file atomic replace имеет те же известные межпроцессные ограничения, что и агентский write_file: это защита приложения по снимкам, а не универсальная OS compare-and-swap транзакция.

EditorDirty IPC передаёт main лишь boolean для защиты окна. Нативный confirmEditorDiscard показывает фиксированный текст и безопасные кнопки; renderer не задаёт произвольную команду или системный путь.

useImperativeHandle даёт App только open/refresh/reset/hasDirty, не саму textarea и не внутренний mutable state. rootRef помогает отбросить ответ чтения уже сменившегося проекта. targetLine сохраняет запрошенную строку до появления нужной вкладки. Номера строк рисуются небольшим видимым диапазоном, а не миллионом DOM-элементов для файла с короткими строками. Имена функций/типов включены в [TS-справочник](reference/typescript.md) и [Python-справочник](reference/python.md).

AST-инструмент [extract_ts_symbols.cjs](../tools/extract_ts_symbols.cjs) дополнен распознаванием React forwardRef, поэтому компонент и его вложенные функции присутствуют в структурном справочнике, как обычные именованные функции.

## Проверки и ограничения

Unit-тесты проверяют CRLF/revision, отсутствие записи до Apply, одноразовые токены, Reject/Cancel, stale до/после diff, чужой root, traversal, бинарный/слишком большой файл. Bridge integration проверяет взаимное исключение agent/editor и сброс предложения при смене проекта. Настоящий Electron smoke открывает две вкладки, сохраняет draft между Chat/IDE, применяет diff, проверяет поиск, защищает закрытие окна и не затирает внешний текст.

Это лёгкий текстовый редактор, не Monaco/VS Code engine: пока нет LSP, подсветки синтаксиса, undo между размонтированием textarea, мультикурсоров, сохранения нового пути/Save As и восстановления ручных drafts после kill всего окна. Создание новых файлов агентом сохраняет прежний отдельный approval-путь. Полный Git/terminal остаются отдельными этапами.

25 октября 2026. Изменения поверх Neutral 7.0.0, база `9572082`.
Выполнен первый этап [плана аудита](40-core-audit-and-roadmap.md).
Следующие этапы не заменены этим набором исправлений.

## Завершение и проверка

`AgentEngine` теперь учитывает `finish_reason=length`, `content_filter` и отказ
модели. Частичный текст остаётся в канонической истории, задача получает `paused`
и понятное объяснение. Вызовы инструментов из оборванного ответа не исполняются,
даже если часть JSON выглядит завершённой. Кнопка продолжения остаётся доступной.
JSON tool calling сохраняет исходную причину завершения вместо принудительного
`stop`; Responses не кэширует оборванный вывод как успешный function call.

`StageVerifier.record_command` сохраняет результат реально выполненной команды
проекта: её идентификатор, программу, exit code и признак успеха. Идентификатор —
hash программы, аргументов и cwd; полный код/вывод в checkpoint не копируется.
Повтор той же команды с успехом заменяет её прежний провал. Успех другой команды
не стирает ошибку. Невыполненные команды без exit code в эти свидетельства не входят.

Итоговая `verification` содержит:

| Статус | Отображение и поведение |
| --- | --- |
| `not_run` | «Ответ получен; проверка результата не подтверждена». Нет утверждения о выполненных тестах. |
| `failed` | Задача приостанавливается, сообщение об ошибке проверки остаётся в карточке и истории. |
| `commands_passed` | Команды завершились успешно; отдельно поясняется, что это не доказывает все требования задачи. |

Карточка `TaskProgress` показывает это состояние, а кнопка хода IDE-задачи различает
полученный ответ и завершение с результатами команд. Обычный Chat и Лола сохраняют
своё прежнее поведение; для них не создаётся фиктивная IDE-проверка.

Это промежуточная мера A1. Полный набор критериев готовности, классификация команд
как конкретных тестов и транзакционный жизненный цикл tools относятся ко второму
этапу. Метод `StageVerifier.verify` ещё не управляет всеми переходами основного цикла.

## Ошибки аргументов и срок задачи

`validate_tool_arguments` применяет JSON Schema до dispatch, включая файловые tools.
Вместо TypeError всего запуска модель получает ошибку поля и может исправить вызов.
Ошибка подготовки diff — также результат инструмента. Подтверждение и проверка
ревизии остаются обязательными для записи.

Лимит runtime от одной минуты теперь действительно означает одну минуту.
Отдельный daemon Timer подаёт существующий сигнал отмены HTTP/tools/approval.
При завершении Timer отменяется. Истечение времени отличается от ручной остановки
в тексте и checkpoint. Ожидание пользователя входит в общий срок; интерфейсный
параметр называется лимитом задачи, а не только временем работы GPU.
Отмена кооперативная: синхронная файловая операция завершается до следующей
проверки Event. Отменяемый поиск относится к четвёртому этапу.

## Сжатие результатов

`compact_tool_result` сохраняет exit code, status, elapsed time и диагностические
фрагменты `output`, `stdout`, `stderr`. Для MCP выбираются текстовые блоки `content[]`;
бинарные изображения и аудио не отправляются как текст. Ошибка в конце длинной
строки может попасть в выборку; размер контролируется после JSON escaping.

Сжатая проекция содержит `source_tool_call_id`, hash и исходную длину; полный
результат остаётся в канонической истории и JSON-экспорте. Архив также сохраняет
краткие свидетельства ошибок команд. Тексты заметок в краткую выдачу не копируются.
Автоматическое дочитывание полного результата через отдельный инструмент ещё
не реализовано: reader/artifact storage остаются третьему этапу.

## MCP

Alias зависит от полного server ID, транспорта, команды/аргументов либо URL и имени
инструмента. Совпадение первых 25 символов больше не смешивает серверы.
Старые имена переводятся в памяти при чтении реестра; явное выключение сохраняется
для каждого нового alias, ссылки плагинов переводятся вместе с ними. Запись происходит
при следующем обычном сохранении настроек. Повторяющиеся имена сервера отвергаются
до замены прежнего каталога.

Discovery резервирует место до создания worker: одновременно одна проверка сервера.
Electron ждёт до 125 секунд при максимуме Python-транспорта 120 секунд; при превышении
срока отправляет cancellation. В настройках показывается ожидание и кнопка
«Отменить проверку». Отмена не публикует опоздавший каталог. Закрытие Core отменяет
и ограниченно ожидает workers. Новые проверки после shutdown запрещены.

## Привязка ключей

`connection_key` применяется к основной модели, модели Лолы и STT независимо.
Смена адреса сбрасывает прежний ключ, включая старое значение из устаревшей формы.
Новый, отличающийся ключ можно ввести вместе с новым адресом. Если намеренно нужен
тот же ключ для другого адреса, сначала сохраните адрес, затем введите ключ заново.
На прежнем адресе отсутствие поля ключа сохраняет его в памяти.

Поле STT URL также очищает введённый ключ сразу в форме. Ключи не попадают в ответы
bridge, реестр чатов и публичный профиль на диске.

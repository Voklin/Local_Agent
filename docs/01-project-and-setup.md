# 1. Назначение проекта и запуск

## Что создаётся

LocalAgent — настольный помощник по программированию. Пользователь выбирает папку, подключает модель через HTTP, задаёт задачу и получает ответ. Модель может предложить вызов одного из четырёх файловых инструментов. Код приложения проверяет аргументы и пути, выполняет разрешённую операцию и возвращает результат модели. Для записи пользователь сначала видит diff.

Пример задачи: «Найди функцию обработки настроек и предложи исправление». Приложение не загружает автоматически весь проект в модель: модель должна запросить нужные файлы через инструменты. При этом содержимое прочитанных файлов становится частью модельного запроса. Если сервер находится на другом компьютере, эти данные отправляются туда.

Слово «локальный» означает настольное приложение и возможность использовать локальный сервер модели. Оно не гарантирует, что любой введённый URL ведёт на локальную машину.

## Реальные возможности Electron

Можно выбрать проект, просматривать папки и UTF-8 файлы, указать сервер и модель, загрузить список моделей, вести чаты, наблюдать генерацию текста и события инструментов. Запись требует отдельного решения для каждого предложения. Задачу можно остановить, затем продолжить из истории с контрольной точкой. URL и ID модели сохраняются, API-ключ в этом пути остаётся в памяти процесса.

Нет готового Windows-инсталлятора, встроенного терминала, инструмента удаления файлов, создания каталогов или произвольного запуска команд. Центральная область показывает файл для чтения. Наличие в старых материалах слова «редактор» не делает текущий React-предпросмотр полноценным редактируемым IDE-компонентом.

## Необходимое окружение

| Компонент | Для чего нужен | Что проверялось |
| --- | --- | --- |
| Python | Запуск ядра, файловые операции, клиент модели | Python 3.12 в локальных проверках и Windows CI |
| Node.js и npm | Установка, разработка и сборка интерфейса | Node.js 24 задан в workflow |
| Сервер с совместимым API | Фактическая генерация модели | Автоматические тесты используют локальные HTTP-фикстуры; пользователь подтвердил работу своей модели |
| Git | История кода, ветки, коммиты | Не обязателен для выполнения Python-ядра, нужен для разработки |
| PySide6 | Только сохранённый Qt GUI и его проверки | Для Electron Core Qt не требуется |

Конкретные npm-версии фиксирует `package-lock.json`. Требования Python записаны диапазонами, поэтому новая установка может подобрать другие допустимые версии. Это разные уровни воспроизводимости.

## Чистая установка Electron

Откройте PowerShell именно в корне репозитория — там, где лежат `package.json`, `agent/` и `run-desktop.bat`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-core.txt
npm ci
.\run-desktop.bat
```

Первая команда создаёт отдельное окружение Python. Вторая устанавливает SDK в него. `npm ci` использует lock-файл и устанавливает дерево JavaScript-зависимостей, включая Electron. Скрипт запуска выбирает `.venv\Scripts\python.exe`, если он существует, и вызывает `npm run dev`.

На уже подготовленном компьютере не требуется переустанавливать всё перед каждым запуском. Достаточно `run-desktop.bat`. После обновления Python-ядра перезапустите приложение: горячее обновление React не перезапускает уже работающий Python-процесс.

## Первое подключение

1. Нажмите «Открыть проект» и выберите отдельную рабочую папку.
2. Откройте настройки модели.
3. Укажите URL, например `http://127.0.0.1:1234/v1`, если ваш сервер действительно слушает этот адрес.
4. При необходимости введите ключ. Для сервера без проверки ключа SDK использует строку `no-key`.
5. Нажмите «Загрузить модели» или введите точный ID модели вручную и сохраните настройки.
6. Начните с запроса чтения: «Какие файлы есть в корне проекта?».
7. Для проверки записи попросите создать небольшой текстовый файл в уже существующем каталоге и изучите предложенный diff.

Число `1234` — исходное значение интерфейса, а не универсальное свойство всех серверов. Суффикс `/v1` уже входит в `base_url`; клиент добавляет путь ресурса, например `/chat/completions`.

## Другой интерпретатор Python

```powershell
$env:LCA_PYTHON = 'C:\путь\к\Python\python.exe'
npm run dev
```

Здесь задан путь к исполняемому файлу, а не к папке. Переменная действует в текущем сеансе PowerShell и наследуется Electron. Ядро должно видеть установленный пакет `openai` именно в этом интерпретаторе.

## Сборка и выполнение — разные действия

`npm run build` проверяет TypeScript и создаёт `apps/desktop/dist/` и `dist-electron/`. Это не упаковка Python и не создание установщика. В текущем development-пути Electron загружает страницу с Vite на порту 5173. Поэтому один только `npm run build` не заменяет `npm run dev` при обычном локальном запуске.

## Сохранённый интерфейс Qt

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

`main.py` создаёт `QApplication` и `MainWindow`. Альтернативный `run.bat` сам создаёт/активирует окружение и устанавливает зависимости, но также содержит старую команду копирования `.env.example`. Такого файла в текущем репозитории нет, а активный `main.py` не загружает dotenv. Это остаток старого сценария запуска, подробно отмеченный в [ограничениях](11-current-status.md).

Qt-настройки хранятся через `QSettings` и не совпадают с новым JSON настроек Electron. В частности, старый диалог Qt сохраняет введённый API-ключ через `QSettings`; обещание «ключ только в памяти» относится к Electron-пути.

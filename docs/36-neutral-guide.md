# Neutral 7: интерфейс, модели и Лола

Neutral — новое имя LocalAgent. Репозиторий и совместимые каталоги данных сохраняют
старые имена, чтобы обновление не потеряло разговоры, голос Serena и настройки.
Основное приложение — Electron. Старый Qt-интерфейс остаётся историческим путём;
новые проекты, расширения и MCP настраиваются в Electron.

## Быстрый маршрут

1. Откройте настройки значком справа сверху или слева снизу.
2. В разделе **Модели** выберите LM Studio, Ollama или OpenAI API.
3. Введите адрес, при необходимости ключ, получите список моделей и выберите ID.
4. Нажмите **Проверить ответ модели**, затем **Сохранить настройки**.
5. Начните разговор в Chat. Для файлов переключитесь в IDE и выберите папку.
6. Значок папки с плюсом в левой панели создаёт проект: имя, общие инструкции
   и необязательная папка для IDE.

Профиль подключения и активная конфигурация — разные вещи. **Сохранить профиль**
запоминает именованный набор параметров; **Сохранить настройки** применяет
конфигурацию к следующим запросам. Это позволяет подготовить несколько вариантов
и проверить их до переключения текущей модели.

## Дизайн и навигация

Внешний вид основан на присланных изображениях: графитовый фон, тонкие границы,
пудровый акцент, небольшая панель режимов, отдельная история и просторный ввод.
Знак Neutral — буква N с точкой равновесия. Исходник находится в
[neutral.svg](../assets/neutral.svg). PNG и многоразмерный ICO генерируются из него
через [generate_brand_icons.py](../tools/generate_brand_icons.py).

| Область | Назначение |
| --- | --- |
| Левая узкая панель | Chat, IDE, Лола; история, файлы, поиск и память проекта |
| Панель пространства | Выбор проекта, его настройки и создание нового |
| Разговоры | Поиск по названию и сообщениям, меню действий, архив |
| Верхний селектор модели | Открывает настройки подключения |
| Ход задачи | Этапы, фактические результаты инструментов и продолжение |
| Поле ввода | Enter отправляет, Shift+Enter добавляет строку |

Ctrl+N создаёт разговор, Ctrl+K открывает поиск разговоров. В IDE Ctrl+P открывает
быстрый поиск файла, Ctrl+Shift+F — поиск по содержимому проекта. Сохранены
горячие клавиши редактора и проверка несохранённых черновиков.

В разделе **Оформление** доступны тёмная и светлая темы, пудровый, лавандовый,
небесный и мятный акценты, плотность, боковая панель, журнал и строка состояния.
Выбор хранится в прежнем ключе `localagent.appearance.v1`. Это совместимость
данных, а не видимое имя продукта. Движение Лолы можно отключить отдельно;
системное `prefers-reduced-motion` также учитывается.

## Подключение моделей

### Локальный или совместимый сервер

Оставьте тип API **OpenAI-совместимый**. Типичные адреса:

- LM Studio: `http://127.0.0.1:1234/v1`.
- Ollama: `http://127.0.0.1:11434/v1`.
- Другой совместимый сервис: его базовый адрес с поддержкой `/chat/completions`.

**Протокол инструментов** управляет только форматом вызовов:

- Native: определения и ответы tools передаются полями API.
- JSON: модель возвращает JSON-команды текстом; адаптер преобразует их в тот же
  агентный цикл. Это полезно для моделей без нативной поддержки tools.

Оба варианта используют один реестр, те же ограничения и подтверждения.

### OpenAI

Пресет **OpenAI API** выбирает `https://api.openai.com/v1` и **Responses API**.
Нужен ключ платформы OpenAI с доступом к выбранной модели. Подписка ChatGPT сама
по себе не является API-ключом. Никакой запрос к платному API не выполняется
при выборе пресета: запрос отправляют кнопка проверки или сообщение пользователя.

Responses поддерживает потоковый текст и функции. Адаптер переводит историю
в `input`, результаты tools — в `function_call_output`, а бюджет ответа —
в `max_output_tokens`. Запросы используют `store=false`. Зашифрованные reasoning
items сохраняются в памяти ModelClient для продолжения цепочки инструментов
в пределах запуска. Они не становятся видимыми сообщениями или озвучкой.

Параметры temperature/top_p не отправляются через этот адаптер: набор допустимых
параметров различается между моделями. Сервер использует собственные значения.
Лимит ответа продолжает действовать. Для совместимых Chat Completions параметры
случайности отправляются как прежде.

Адреса с паролем, ключом в query string, fragment или неверным портом отклоняются.
При смене адреса поле ключа очищается, чтобы прежний ключ не ушёл другому серверу.
Профили записывают только публичные настройки; API-ключ остаётся в памяти процесса.
После закрытия приложения его нужно ввести снова.

### Диагностика

**Получить модели** проверяет сервер, но не гарантирует, что каждая модель загружена.
**Проверить ответ** делает короткий запрос без проекта и истории с общим deadline
и ограничением размера ответа. У reasoning-модели бюджет может закончиться до
видимого текста; увеличьте бюджет или настройте рассуждения на сервере.

Сетевые ошибки и HTTP 429/500/502/503/504 повторяются максимум два раза до получения
ответа. Уже начавшийся поток не повторяется автоматически: это предотвращает
дублирование действий. Стоп отменяет активный запрос.

## Лола

Для Лолы сохраняется отдельная модель и отдельная история в каждом пространстве.
В её расширенных настройках отдельно выбирается совместимый API или OpenAI Responses;
протокол основной модели не подменяет этот выбор.
Обычные вопросы, время, расчёты, заметки, таймеры, музыка и разрешённые действия
на компьютере она выполняет сама. Сложность вопроса не запускает делегирование.

Запрос программирования проходит `is_coding_request` по исходному тексту человека.
В этом случае первый запрос Лолы требует `delegate_task`; IDE предназначена для
файлов, Chat — для обсуждения кода. Сервер повторно проверяет исходное намерение,
поэтому модель не может разрешить передачу, просто переписав обычный вопрос
в аргументах инструмента. Пограничные естественные формулировки остаются
эвристикой: для неоднозначного запроса лучше явно написать, что речь о коде.

При включённой автоматической передаче основной агент начинает подготовленную
задачу. Если автоматическая передача отключена, интерфейс показывает задание
и кнопку выполнения. Результат основной модели возвращается в историю Лолы.

Ответы Лолы и вход TTS проходят очистку: Markdown, звёздочки, заголовки, ссылки,
технические блоки и внутренние reasoning-теги не озвучиваются. Слова и значимые
числа сохраняются; `2 * 3` становится «2 умножить на 3». Блок кода заменяется
указанием посмотреть код в основном чате. Очистка действует и на окончательную
сохраняемую историю, и на показ потокового ответа.

Голос, громкость, скорость, характер и отдельная модель доступны в **Голос и Лола**.
Расширенная настройка STT/TTS и кнопка настроек на экране Лолы продолжают работать.
Переключение на новый бренд не переобучает и не меняет файлы Serena.

## Удаление прежних ролей IDE

Начиная с 7.0 действует один `AgentEngine` для основной модели. Панели дирижёра,
автора, сборщика и проверяющего удалены вместе с их lifecycle-кодом. Этапы в ходе
задачи — состояния одного агента, а не отдельные модели.

Старые разговоры можно читать. Контрольную точку прежнего workflow нельзя
продолжить новым движком: приложение объяснит это и предложит новую задачу.
История, результаты, файлы и прежний JSON настроек ролей не удаляются автоматически.
Исторический этап описан в [главе 34](34-ide-roles-and-model-lifecycle.md).

# План UI/UX-переработки Neutral

Статус: прототипирование и проверка. Интеграция в основное приложение ожидает одобрения владельца. Прототип изолирован от действующего интерфейса и Python backend; демонстрационные данные не являются результатами работы агента.

## Текущая итерация

Работа ведётся только в app.js/app.css и review-ui.js/review-ui.css. История IDE переносится к агенту; пробелы отчёта представлены интерактивными локальными примерами. Лола остаётся всплывающим окном. После визуальной проверки остановиться для оценки дизайна. Подключение backend и замена компонентов основного приложения требуют утверждения пользователя.

## Цель и границы

IDE должен сохранять контекст проекта, открытый файл и состояние агента одновременно; Chat — отдавать приоритет разговору, истории и действиям агента. Оба режима используют общие компоненты, типографику, цвета, размеры и правила фокуса. Лола и функции, не представленные в прототипе, остаются частью продукта и требуют отдельной проверки при интеграции.

## Перед интеграцией

1. Согласовать компоновку и поведение обоих прототипов по скриншотам и интерактивному запуску; явно зафиксировать замечания.
2. Сверить каждый элемент с картой возможностей в `UI_UX_AUDIT.md`. Сохранить действующие операции, статусы, разрешения и пути восстановления. Не превращать доступные функции в декоративные кнопки.
3. Сопоставить состояния прототипа с реальными событиями `useTaskSession`, настройками, редактором, историей и API preload. Данные и побочные действия должны приходить из существующих сервисов, не из демонстрационных сценариев.
4. Внедрять дизайн-систему поэтапно, сначала общие примитивы и каркас, затем IDE и Chat; не менять backend без подтверждённой технической необходимости. Сохранить существующие пользовательские данные и состояние несохранённых файлов.
5. Проверить клавиатуру, доступные имена, ловушку и возврат фокуса в диалогах, контраст, корректность небольшого окна и сохранение настройки панелей. Проверить блокировку фоновых shortcuts при открытом native dialog.
6. Провести визуальную и функциональную проверку Electron при 1280×720, 1440×900 и 1920×1080: пустой экран, файл, разговор, активная задача, подробности инструментов, настройки, ошибки и запросы подтверждения. Отдельно проверить восстановление задач и переключение чатов.
7. Запустить сборку, типизацию и профильные проверки Electron, включая реальный backend и сохранение настроек. Исправить обнаруженные регрессии до завершения интеграции.

## Критерии приёмки после одобрения

- Все существующие пользовательские операции доступны и корректно выполняются; ошибки и незавершённые действия видимы.
- Изменения файлов и внешние действия сохраняют действующий порядок подтверждений и восстановления.
- Панели можно настраивать без потери состояния; фокус и доступность не ухудшены.
- Пропорции, текст, контраст и переполнение проверены на трёх размерах окна; реальные состояния проверены с живым приложением.
- Сборка и относящиеся к изменениям проверки проходят; известные ограничения задокументированы.

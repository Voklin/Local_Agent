# Автоматический контекст и размещение Лолы

26–27 октября 2026. По уточнению пользователя сборка установщика приостановлена.
Эта глава описывает изменения исходников после [этапа 9](54-core-reliability-stage9.md).

## Что выбирает пользователь

В «Настройки → Контекст и лимиты» установлен режим **Автоматически**.
Достаточно указать сервер и модель. Числовые поля окна, ответа, числа циклов и
времени задачи скрыты; Temperature, Top P и политика памяти остаются доступны.
Тот же переключатель используется в настройках модели Лолы. Старые профили без
`budget_mode` переходят в auto при чтении. Ключи и история не переписываются.

Режим **Вручную** возвращает прежние поля и presets 4K/8K/32K. Явно сохранённый
manual остаётся manual. В нём проверяются числа и соотношение ответа с окном.
Поле `max_tokens` старого профиля больше не ограничивает основной auto-цикл:
его стартовая цель — до 8192 токенов, затем применяется реальное доступное место.
Проверки модели, исследователь и другие служебные запросы сохраняют свои
отдельные небольшие цели ответа.

Во время задачи «Контекст и расход» показывает найденное окно, источник данных,
оценку входа, резерв ответа, сжатие и число отложенных схем инструментов.
Фактический usage сервера отображается отдельно от оценки.

## Почему прежний бюджет мешал коду

Старый счётчик приравнивал каждый UTF-8 байт JSON к токену. Кириллица занимает
несколько байтов; код, schemas и экранирование также раздували оценку. Дополнительно
полный максимум ответа резервировался даже в маленьком окне. Поэтому запрос мог
отклоняться самим Neutral задолго до физического предела модели.

После `write_file` большой код оставался в аргументах исторического вызова.
Повторная отправка уже записанных десятков килобайт могла заблокировать следующий
шаг даже при маленькой квитанции об успешной записи.

## Как работает новое ядро

1. [auto_budget.py](../agent/auto_budget.py) определяет загруженное окно только
   read-only запросами к настроенному локальному серверу. Для LM Studio берётся
   `loaded_instances[].config.context_length`, для прежнего API —
   `loaded_context_length`; для Ollama — `/api/ps`, для llama.cpp — `/props`.
   Заявленное в имени/metadata обучающее окно не считается загруженным.
2. Metadata ограничены 512 КБ, общий timeout около секунды; есть cache на 30 секунд.
   При JIT-загрузке LM Studio профиль повторно уточняется после начала работы.
   Если сервер ещё не сообщил окно, используется временная оценка 32 768 с явной
   отметкой в источнике. Старое числовое поле manual не становится пределом auto.
   Оценка уточняется по loaded metadata или явному context rejection до SSE.
   Это не подтверждение размера и не команда загрузить модель с таким окном.
3. Для уже загруженного anonymous LM Studio доступен `lmstudio==1.5.0`: только
   `list_loaded()` и `count_tokens()`. Нет вызова `model()`, `load()` или unload.
   SDK ограничен timeout, проверяет отмену, кэширует до 16 подсчётов и закрывается
   вместе с ModelClient. При ключе API, несовместимом адресе или ошибке SDK
   используется языковая оценка с запасом. Даже tokenizer сериализованного prompt
   не считается точным подсчётом chat template сервера.
4. [RequestBudget.fit](../agent/request_budget.py) измеряет окончательный prompt
   после Chat/JSON/Responses адаптеров. Подбирает ответ по оставшемуся месту,
   уплотняет старую историю, при необходимости оставляет компактный набор schemas.
   `discover_tools` находит остальные разрешённые инструменты; их полные schemas
   появляются на следующем шаге. Для тесного окна есть вторая ступень: только
   каталог и уже выбранные инструменты. Отключённые инструменты не включаются поиском.
5. Полностью парные исторические большие `write_file`/`patch_file` проецируются
   в assistant-архив с именем, краткими аргументами, SHA-256, результатом и source
   anchors. Это обозначенные данные истории, не новые команды. Канонические
   аргументы не меняются. Код читается через `read_range`, полный результат —
   через `read_tool_result`. Вызов без полного набора ответов не сокращается.
6. Явный отказ HTTP 400/413/422 с размером контекста позволяет уточнить окно,
   увеличить запас и повторить ещё не начавшийся запрос. Общий транспортный цикл
   ограничен тремя попытками. После начала SSE такой повтор не применяется.
   Фактический prompt usage дополнительно корректирует оценочный запас.
7. На локальном endpoint при `finish_reason=length` есть до двух продолжений
   текста с одним UI message_id и одним сохранённым ответом. Для оборванного
   tool call запрашивается заново полный небольшой вызов; частичный вызов не
   исполняется. Неизвестный EOF, refusal и transport error остаются отдельными
   состояниями, а не превращаются в успешное завершение.

Автоматическое обнаружение не меняет GPU offload, KV cache, batch, context loading
или конкурентность в LM Studio. Оно не устраняет физический предел памяти модели.
Огромные обязательные инструкции или сам текущий запрос могут не поместиться;
в этом случае история сохраняется, предлагается передать текст файлом или начать
новый чат. Текущий запрос и инструкции не обрезаются ради зелёного индикатора.

## Локальная длительная работа

Для auto на loopback/private IP/`.local` endpoint нет суммарного лимита циклов,
вызовов инструментов и минут всей задачи. Сохраняются Stop, отмена, защита от
повторяющихся действий и ошибок, подтверждения записи, ограничения отдельного
процесса/команды и timeout сетевой операции. На публичном API сохраняются конечные
пределы задачи. Адрес сервера определяет эту политику; локальный proxy сам по себе
не доказывает, что вычисления или биллинг происходят локально.

Полная история остаётся на диске. Уплотнение — изменяемая проекция одного запроса,
а не удаление чатов или исходного кода. Новых фоновых LLM-запросов для сжатия нет.

## Лола без обрезания

Прежние `clip-path` отрезали края волос, руки и части поз. Равномерная сетка atlas
также не совпадала с реальными краями всех рисунков. Дополнительно intrinsic размер
внутреннего блока мешал уменьшению персонажа при большом масштабе окна.

[LolaAvatar.tsx](../apps/desktop/src/LolaAvatar.tsx) теперь использует SVG viewports
по 28 проверенным source rectangles нового исходного PNG. Все позы размещаются на
общем canvas 260×260 с нижней линией 247, сохраняя поля вокруг головы и обуви.
Нет боковой или polygon маски через персонажа. PNG не редактируется при рендеринге;
точный prompt сохранён рядом с asset. Старая версия сохранена как история дизайна.

На маленькой рабочей области и при увеличенном масштабе свободное место определяет
высоту персонажа; SVG сохраняет пропорции и показывает полный рост. Панель ответа
прокручивается отдельно. Семь состояний и четыре кадра каждого остаются CSS-анимациями;
reduced motion отключает движение. Размер native окна ограничен workArea монитора
в DIP. При обычном изменении размера сохраняется нижний центр окна, затем применяется
ограничение экрана. В настройках и трее добавлено возвращение в угол экрана.

## Проверка и запуск

[Автоматические тесты](../tests/test_auto_budget.py) используют настоящие локальные
HTTP metadata/400/SSE fixtures, проверяют русский текст, 4K окно, deferred schemas,
неизменность текущего запроса, большой выполненный write и нетронутый pending call.
[StreamingTests](../tests/migration/test_streaming.py) проверяет продолжение через
настоящий TaskService, один UI id и одну каноническую запись. Реальная большая
модель для этих тестов не загружается.

Electron smoke проверяет auto/manual UI, семь состояний Лолы, малое окно и масштаб
150%, отключение анимации, click-through, drag, один Core и один пользовательский
запрос при скрытом основном окне. PNG снимки находятся в `.test-data/lola-gui/`.
Итог: 350 unit-тестов OK (один Windows symlink privilege skip), 81 HTTP/Core тест OK;
typecheck/build, общий GUI smoke, Neutral IDE/MCP/rollback, optional IDE и настольная
Лола прошли. Логи: `.test-data/auto-budget-{unit,http,build}-final.log` и
`.test-data/auto-budget-{general,neutral,optional,lola}-smoke-final.log`.
Ручные числовые caps проверяются в явно выбранном manual, а переход manual 4K →
auto не переносит старое окно как скрытый предел. Тестовая модель IDE читает
evidence также из сжатого архива; подтверждённый patch доказывает наличие файла
и его родительского каталога в этом сценарии.

Read-only проверка настоящего LM Studio и SDK прошла: на момент проверки список
загруженных моделей был пуст. Проверки генерации на реальной LLM не заявляются;
большая модель не загружалась. Новые зависимости установлены в `.venv` и
`.venv-test`; `pip check` обоих окружений прошёл.

Изменения остаются в рабочей копии ветки `codex/electron-agent-bridge` поверх
`9572082`, вместе с сохранёнными предыдущими изменениями. Новых commit/push,
слияний или релизов в этом запросе не выполнялось.

Для запуска текущих исходников используйте [run-desktop.bat](../run-desktop.bat).
Нужна перезагрузка уже открытого приложения. Установщик и замена установленной
копии по текущему запросу не выполняются; прежние EXE не содержат эти изменения.

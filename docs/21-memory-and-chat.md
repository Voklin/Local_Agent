# 21. Память проекта и читаемый чат

В IDE кнопка «Память проекта» открывает семь редактируемых полей: описание, текущий фокус, следующие шаги, решения, ограничения, соглашения и важные файлы. Списки вводятся по пункту на строку. Личный Chat не использует память проекта. Заметки остаются справочными, могут устаревать и не дают модели дополнительные разрешения.

## Сохранение и конфликт

`get_project_memory` не создаёт файл. Он читает strict UTF-8 JSON до 200 КБ (этого достаточно для полного разрешённого набора четырёхбайтных Unicode символов), проверяет поля и возвращает SHA-256 исходных байтов. Отсутствующий файл имеет revision хеша пустых байтов. Некорректный/слишком большой store показывает ошибку; UI не предлагает сохранить поверх повреждённых данных.

`save_project_memory` требует ровно семь editable keys, исходную revision, корректные типы/длины/count и отсутствие NUL. Проверки ручного API строже исторического validate_memory: вход не обрезается молча. Для строк лимиты 1200/600/800 символов, для decisions/constraints/conventions до 30×300, important_files до 40×240. Store нормализует whitespace и deduplicates списки тем же способом, что и auto-memory.

Общий MEMORY_LOCK используется manual write и save_project_memory модели. Под RLock проверяется свежая revision и выполняется atomic temp/fsync/replace. Если после открытия модель/другое окно изменило данные, MEMORY_CHANGED оставляет draft в модальном окне. Закройте его после копирования нужного текста и откройте память заново для свежей версии. Закрытие dirty формы требует отдельного явного отказа от сохранения.

Это process-local синхронизация. Внешний процесс, редактирующий JSON одновременно между compare и replace, не подчиняется RLock; межпроцессный filesystem CAS не заявляется. Утилита не очищает архивы или память автоматически. В процессе активной задачи manual Save запрещён, чтобы не менять базу знаний посреди выполнения. Root берётся из bridge, а не из произвольного пути renderer.

## Имена чатов

У записи истории есть кнопка «Переименовать чат». Отдельный диалог принимает непустое название до 120 символов. Core проверяет chat ID, idle и точное соответствие project_root текущей области (пустая область для Chat). Меняются title/updated_at и производный индекс, сообщения/контрольная точка остаются. Если переименован выбранный чат, его title обновляется и в TaskService, чтобы следующая запись истории не возвращала старое имя.

## Код и прокрутка

ChatText разбирает отдельные строки с тройными backticks и выводит обычный текст или блок кода с подписью языка/кнопкой копирования. Незакрытый fence поддерживает потоковую генерацию. Разбор memoized по text. Это ограниченный parser, не полный Markdown: HTML, ссылки и произвольные теги не исполняются. Даже `<script>` внутри ответа остаётся текстом. Подсветки синтаксиса пока нет. Copy использует Clipboard API, при отказе предлагает выделить текст вручную; fence и label в копию не попадают.

Пока читатель находится в пределах 80 px от конца, новые сообщения/дельты прокручивают вниз. После прокрутки вверх follow выключается; новые ответы не перебрасывают к низу. Кнопка «К последнему сообщению» возвращает следование. При смене/создании чата режим follow сбрасывается. Самостоятельного window.scroll для чатового текста нет.

## Проверки

Unit tests памяти покрывают round trip, stale revision после auto-memory, invalid payload без записи, corrupt store без потери, изоляцию root и максимальный Unicode budget. Service/process тесты проверяют scope и busy rename. Electron smoke редактирует/сохраняет память, переименовывает чат, проверяет React escaping и Copy argument. Clipboard API в smoke подменяется capture-функцией: системный буфер пользователя не меняется. Отдельный длинный SSE ответ проверяет, что после scroll вверх следующий chunk не двигает viewport и кнопка follow возвращает вниз.

CI уточнил контракт fixture: Windows runner может давать TemporaryDirectory через 8.3 alias. Root теста теперь canonical, как set_project и project_root движка; иначе raw helper сохранял заметки в другом историческом path-hash, а manual API правильно читал canonical scope. Проверки stale/corrupt сохранены без ослабления assertions.

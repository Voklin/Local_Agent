## Порядок на пятичасовой сеанс

### A1. Рабочий IDE-редактор

Сценарий: открыть несколько UTF-8 файлов, переключаться между вкладками, редактировать, найти текст/строку и сохранить конкретный подтверждённый diff. Несохранённые вкладки не теряются при смене Chat/IDE; закрытие вкладки/проекта/окна защищено от случайной потери.

Backend: отдельный editor service, strict UTF-8, исходный snapshot при чтении, preview без записи, одноразовый proposal ID. На Apply повторно проверяются project/path/hash/content; используется существующая атомарная write_file. Старая версия файла на диске блокирует Save/Apply. Ни прямого write из renderer, ни молчаливого сохранения по Ctrl+S. Агент и ручной editor не пишут одновременно.

UI: вкладки, dirty-индикатор, номера строк, перенос, позиция курсора, Ctrl+S, Ctrl+F, переход к строке, reload. Общая палитра сохраняется.

Приёмка: unit/bridge тесты reject/cancel/stale/outside/binary/размера; Electron открывает два файла, сохраняет после diff, сохраняет drafts между режимами, не перезаписывает внешнее изменение. Handbook и AST обновлены.

### A2. Поиск и навигация по проекту

Сценарий: найти строку в проекте, увидеть файл/номер и открыть результат в редакторе; быстро открыть файл по имени. Не требовать модель для простой навигации.

Ограниченный обход внутри root, исключения .git/node_modules/venv, без выхода по symlink; лимиты файлов/байтов/результатов/времени и честный truncated. Фоновый worker/отмена оставляют Stop/health отзывчивыми. Горячие клавиши Ctrl+Shift+F и Ctrl+P, доступная форма и пустые/ошибочные состояния.

Приёмка: fixture traversal/Unicode/large/timeout/cancel/outside; настоящий Electron переход к найденной строке. Нельзя выдавать неполную выдачу за полный анализ проекта.

### A3. Встроенные локальные GGUF-модели

Сценарий из прежних чатов: выбрать уже имеющийся GGUF и llama-server, настроить context/GPU layers, запустить/остановить собственный runtime, получить endpoint и явно применить его к агенту.

Сначала укрепить старый LocalRuntime: постоянное чтение bounded stdout, отменяемый startup/readiness, строгая валидация параметров и владение процессом. Никаких произвольных extra_args из renderer, shell=True, автоматических загрузок моделей или остановки чужого LM Studio. Файлы модели/runtime выбираются нативным диалогом; большие GGUF не копируются без необходимости. Явно отличать downloaded/starting/ready/failed/stopped, не писать «готово» до HTTP readiness.

Приёмка: subprocess-стенд имитирует server startup/ошибку/многословный stdout/Stop; Electron выбирает ресурсы и видит состояние. Проверка с настоящим llama.cpp/GGUF только если подходящие ресурсы уже доступны; иначе честно указать, что реальное GPU-исполнение не подтверждено. В этом случае не скачивать гигабайты и продолжить независимые этапы.

### A4. Память, история и читаемый чат

Дать просмотр/контролируемое редактирование компактной памяти выбранного проекта; сохранить существующие ограничения полей и изоляцию. Добавить переименование чатов в своей области, удобные code blocks/copy и авто-прокрутку только пока читатель находится внизу. Содержимое модели остаётся текстом, HTML не исполняется. Не удалять пользовательские архивы автономно.

Приёмка: память не смешивается между проектами/Chat, invalid payload не портит store, scopes чатов соблюдаются, UI не перескакивает вниз во время чтения старого ответа.

### A5. Первый работающий слой голосового режима

После ядра IDE и моделей: начать с управляемой пользователем озвучки/остановки и состояния персонажа; затем подключать push-to-talk/STT через отдельные provider-контракты при наличии времени и доступных зависимостей. Микрофон только после явного пользовательского действия в приложении, никаких фоновых записей или отправки аудио случайному сервису. Не подменять рабочую функцию декоративной кнопкой. Без доступного провайдера оставить честное disconnected и документировать конкретный следующий шаг.

Приёмка: детерминированные UI/provider-фикстуры проверяют переходы/Stop/cleanup. Не считать голос проверенным на настоящем микрофоне по тестам заглушек.

### A6. Интеграция и итог

Зарезервировать время до срока на финальные регрессии, документацию, commit/push в текущий draft PR, CI и актуальный локальный пакет, если успевает собраться. Проверки модели проводить в искусственных временных проектах. Чистая VM install/upgrade/uninstall остаётся отдельным критерием и не имитируется обычным packaged smoke.

## За пределами текущего обязательного объёма

Полноценный интеллектуальный planner/stage verifier с запуском тестов, MCP transport, общий терминал, credential store, Git write operations, загрузчик моделей из сети, Live2D/wake word и облачные платные STT/TTS — отдельные проектируемые этапы. В этом сеансе можно описать их контракты/критерии, но не подключать опасный общий shell или объявлять готовым весь backlog.

## Правила работы и проверок

Рабочая копия общая с пользователем: сначала git status и инструкции, чужие изменения не сбрасывать. Не менять `.codex`/памяти Codex, пользовательские проекты, системные настройки или установленные модели. Установщики можно собирать как проверяемые артефакты; merge, release и установка не разрешены. Не отправлять сообщения в другие чаты: доступ к предыдущим беседам дан для чтения.

Законченный этап: поведение + соответствующие тесты + подробная глава + AST references + просмотр diff + небольшой commit + обновлённый существующий PR + проверенный CI. Не запускать одновременно тяжёлую упаковку и чувствительные crash-тесты. Реальный LM Studio не заменяет HTTP-фикстуры; невозможную проверку описывать как невозможную, а не успешную.

Проверять clock перед каждым новым этапом и публикацией. В конце срока перечислить отдельно completed/partial/not started, точный SHA/dirty files, PR/CI, оставшиеся собственные процессы и следующий безопасный шаг. Если упёрлись в решение владельца — зафиксировать его и выполнять независимые пункты, пока есть время.

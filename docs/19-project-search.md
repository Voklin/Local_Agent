# 19. Поиск по проекту и быстрое открытие

Поиск не вызывает модель: Electron передаёт запрос Python Core, отдельный поток читает только выбранную папку. Ctrl+Shift+F открывает боковую панель, Ctrl+P — окно быстрого открытия. В боковой панели введите текст, при необходимости маску `*.py` или `src/*` и включите учёт регистра. Кнопка «Найти» запускает поиск. Клик по результату открывает файл на найденной строке; существующий несохранённый editor draft сохраняется. Поиск читает диск, поэтому номера строк могут отличаться от несохранённого draft.

Быстрое открытие ищет подстроку в относительном пути. После паузы ввода 250 мс появляется список; стрелки меняют выбор, Enter открывает, Escape закрывает. Пустой запрос показывает ограниченный список доступных файлов. Список следует порядку обхода файловой системы; ранжирования и fuzzy matching пока нет.

## Протокол и разделение ответственности

`project:search` → `search_project` принимает `mode` (`text`/`files`), `query`, `pattern`, `case_sensitive`, `limit`. Ответ содержит `matches`, `scanned_files`, `skipped_files`, `truncated`, `reason`. Text match содержит относительный `path`, 1-based `line`, первые 300 символов строки. Files match содержит путь и размер; содержимое не читается.

`ProjectSearchService` разрешает один worker. Root и параметры фиксируются до запуска. Флаг running снимается до отправки ответа, чтобы следующий запрос мог стартовать сразу после получения предыдущего. `cancel_project_search` устанавливает отдельный threading.Event; отмена поиска не отменяет задачу агента. Смена папки и завершение bridge тоже отменяют поиск. Main bridge не ждёт поиска и продолжает обрабатывать JSON-lines запросы.

React хранит монотонный ticket. Перед новым запросом он отменяет и дожидается предыдущего, а перед публикацией проверяет ticket и корень. Скрытие панели/закрытие quick open инвалидирует запоздалый ответ. Ошибки показаны текстом; автоматических бесконечных повторов нет.

## Границы обхода

Root проходит canonical_root, каждый entry — resolve_allowed_path. Symlink пропускаются; канонический путь junction за пределы root отвергается. Посещённые канонические папки не обходятся повторно. Это application-level проверка, а не защита от конкурентной подмены файлов ОС.

Исключены служебные каталоги из IGNORED_DIRS, тестовые окружения/данные, build/dist/artifacts. Не используются `.gitignore` и индекс Git. Поиск буквальный, без regex. Маска сопоставляется с относительным путём без учёта регистра; регистр текста определяется checkbox.

Бюджеты: 3 секунды cooperative deadline, 15 000 обычных файлов, 30 000 entries, глубина 30, суммарно 10 МБ прочитанных данных. Text search читает strict UTF-8 файлы до 1 МБ, пропускает NUL и ошибки чтения. До 200 текстовых результатов или 1000 путей в UI (API до 2000 путей). При достижении лимита показано «часть проекта» с причиной. Счётчик пропусков объединяет большие, бинарные, некорректно закодированные и недоступные файлы. Системный блокирующий filesystem read не прерывается мгновенно; deadline проверяется между операциями.

## Проверки

Unit fixtures покрывают кириллицу, строки/маску/регистр, literal matching, budgets, cancel, invalid root и single-flight worker. Symlink-тест явно пропускается на Windows без соответствующего privilege. Process-тест вызывает реальный JSON bridge. Electron smoke запускает поиск, открывает строку, вызывает Ctrl+P и открывает второй файл, затем продолжает проверки editor approval, конфликтов и остановки модели.

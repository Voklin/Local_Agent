# Качество ответов: измерения и первые исправления

28 октября 2026. По запросу пользователя после полного [этапа 12](68-subagent-profiles.md) основной roadmap временно отложен. Приоритет — корректные и полезные ответы при экономном числе запросов.

## Подтверждённые проблемы и изменения

1. Раньше auxiliary проверка завершения использовала bool(parsed.complete): строка "false" превращалась в True. [parse_completion_assessment](../agent/response_outcome.py) теперь принимает только настоящий JSON boolean; отвергает дубликаты, нечисловые значения, произвольные префиксы и неверные типы. Поддержан чистый fenced JSON. Недоступная/невалидная оценка помечается unavailable, не называется подтверждением; штатный StageVerifier остаётся обязательным. Ошибка бюджета не проглатывается как успешная проверка.
2. После двух отрицательных оценок engine раньше принимал следующий ответ без проверки. Теперь последняя отрицательная оценка завершает цикл как paused с причиной. Доработок по-прежнему две, бесконечного self-review нет. Для обычных информационных вопросов дополнительного verifier request нет.
3. На реальной Gemma наблюдалось нарушение явного формата путь:строка: модель вернула app/totals.py:def tax_total(subtotal):. [answer_format_issue](../agent/response_outcome.py) проверяет только явно запрошенный формат ссылки. Допускается одна текстовая доработка на существующих результатах, без повторного исполнения tools. Повторное нарушение сохраняет текст и приостанавливает задачу. Проверка синтаксиса не доказывает правильность номера строки — это проверяет отдельный oracle benchmark.
4. Инструкция итогового ответа уточнена: прямой ответ, соблюдение формата, ссылки на прочитанные источники, различие записи и проверенного кода, честное описание выполненных тестов и предположений. Не добавляется отдельная редакторская модель на каждый ответ. Это инструкция, а не гарантия устранения галлюцинаций.
5. Существующее bounded восстановление пустого terminal ответа проверено отдельным regression: модель получает просьбу дать текст по уже полученным результатам; пустота не объявляется completed.

Изменены [AgentEngine](../agent/engine.py), [response_outcome](../agent/response_outcome.py), добавлены [тесты качества](../tests/test_response_quality.py). answer_quality/completion_assessment — дополнительные поля checkpoint, SQLite schema не меняется. История не очищается; неверные попытки сохраняются.

## Реальный LM Studio и воспроизводимость

Использована уже загруженная **Gemma 4 E4B Instruct Q4_0** через native tool calling. Других моделей не загружали и не выгружали. Снимок сервера показывал context 131072, eval batch 2048, physical batch 512, parallel 4; параметры LM Studio этим прогоном не менялись. Runner использовал свой ограниченный manual профиль 8K, temperature 0 и seed 0, сохранённые в отчётах. Fixture проекты и профили изолированы в .test-data. История и исходники пользователя не отправлялись: только synthetic corpus.

Одинаковые две задачи: найти точное определение с provenance и исправить налоговый множитель с held-out AST/арифметической проверкой.

| Прогон | Успех | HTTP | Время | Наблюдение |
|---|---:|---:|---:|---|
| quality-gemma-before | 2/2 | 11 | 28.648 s | Исходный контроль перед изменениями ответа |
| quality-gemma-after | 1/2 | 10 | 22.741 s | Код исправлен, формат ссылки неверен; отчёт сохранён как неуспех |
| quality-gemma-format | 2/2 | 10 | 21.327 s | Финальный source-format guard присутствует; обе задачи прошли |

Полные reports/transcripts/source snapshots: .test-data/quality-gemma-{before,after,format}/report.json. Повтор запуска: tools/benchmark_agent.py --out НОВЫЙ_КАТАЛОГ --model gemma-4-e4b-it --protocol native --sizes small --cases definition bugfix --context-pack --live.

По одному прогону двух маленьких задач нельзя заявлять статистическое улучшение, ускорение или поддержку произвольных больших проектов. Эталонный oracle запускался runner отдельно; его успешность не означает, что сама модель запустила тесты. JSON-quality gate Qwen 2.5 Coder остаётся открытым.

## Проверки и дальнейшая работа

Финальные общие проверки: **458 unit, 2 platform skips; 107 Core/HTTP**, npm build и документация (88 Markdown, 3763 локальные ссылки) прошли. Логи: stage12-quality-unit.log, stage12-quality-http.log, stage12-quality-build.log. В HTTP-журнале присутствуют ожидаемые сообщения отрицательных TTS timeout/disconnect fixtures, итог OK.

40 связанных tests в quality-contract-accepted.log прошли: parser/пустой ответ/формат/bounded completion/ядро/профили/настоящий child dispatch. Предыдущие ошибки тестового fixture (task_id и terminal finish_reason) исправлены; production outcome contract не ослаблялся.

Следующий приоритет качества: расширить повторяемую выборку вопросов и кодовых задач, проверить полноту ответа и фактические ссылки, затем отдельно JSON-модель без native tools. Менять одну причину за раз и сохранять неуспешные результаты. Продолжение roadmap 16/17 требует возвращения пользователя к основному плану.

Для отката поведения ответа достаточно восстановить AgentEngine/response_outcome из своего сохранённого snapshot; данные профилей субагентов не зависят от этих полей. Установщик не собирался.

Финальный настоящий Electron smoke также прошёл: stage12-quality-electron.log, результат 22 synthetic HTTP, отдельный профиль; screenshot списка субагентов осмотрен.

## Сильные стороны, которые важно сохранить

- Проверки и восстановление имеют реальные отдельные состояния: «Ответ получен», «Проверены выбранные файлы», stale evidence, recovery и прерванный откат. Это полезнее единой декоративной отметки «Готово».
- Запись файла, команды, MCP и отправка исходников имеют конкретные диалоги просмотра. «Решить позже» позволяет вернуться к задаче через фоновые запуски.
- Редактор объясняет, что агент видит версию на диске, а черновик ещё не записан; сохранение проходит через diff.
- Search показывает отмену, количество проверенных файлов, неполное покрытие, состояние индекса и fallback символов к тексту.
- История имеет поиск, проекты, архив и ветвление; удаление проекта явно отделено от удаления файлов.
- Есть focus-visible и prefers-reduced-motion; темы основаны на общих CSS-переменных.
- Панель progress имеет ограниченную прокрутку, явную кнопку закрытия, Escape и возврат фокуса. Её скрытие не останавливает задачу.

## Свежие визуальные наблюдения

В основном рабочем сеансе приложение запущено через `npm run dev` в отдельном профиле; просмотрены пустые Chat и IDE в окне примерно 1488×934. Файлы скриншотов не сохранены, поэтому эти наблюдения не являются набором визуальных регрессий.

- **Chat:** крупная промо-композиция занимает центр пустого разговора; вспомогательные подписи воспринимаются мелкими и малоконтрастными. Статический разбор размеров текста подтверждает риск читаемости UX-11; количественное измерение контраста не проводилось.
- **IDE:** центральный Welcome одновременно показан с повторным приветствием и карточками в узкой правой панели. Повторение подтверждается исходниками EditorPanel и App/Welcome; визуально оно создаёт конкурирующие центры внимания. Рекомендуется одно основное пустое состояние с коротким объяснением в соседней области.

При минимальном окне, изменённом DPI, в светлой теме, с реальной длинной историей и при работе модели свежая визуальная проверка для этого аудита пока отсутствует.

## Риски изменения дизайна

1. **Потеря функций при упрощении.** Не удалять «В работе», recovery, подтверждения, историю запусков, WorkspaceReview и дополнительные инструменты ради чистого макета. Сводку можно сделать компактнее, подробности должны оставаться достижимыми.
2. **Расхождение оформлений.** Каскад нескольких поколений CSS содержит повторные правила для shell, sidebar, settings и IDE. Правки общих селекторов требуют проверки Chat, IDE, Лолы, native dialog и обеих тем; новый слой overrides без ограничения области увеличит связанность.
3. **Состояние при переключениях.** Busy, navigationBusy, dirty editor, workspaceWorking и backgroundRuns имеют разные значения. Единый disabled на весь интерфейс может заблокировать допустимое открытие фонового разговора или разрешить запрещённую смену проекта.
4. **Настройки при фоновом запуске.** App передаёт в ModelSettings busy текущего разговора, а не anyRunning. Нужно отдельно проверить UX и backend-контракт смены конфигурации при задаче в другом разговоре; статический аудит не доказывает повреждение задачи.
5. **Длинная история и streaming.** Лента отображает все сообщения, ChatText повторно разбирает изменяющийся текст, автоматическая прокрутка зависит от состояния near-bottom. Снижение производительности не измерено; проверить длинные ответы и историю перед добавлением тяжёлого Markdown renderer.

## Проверка обновлённого интерфейса

Минимальный набор ручной/сквозной проверки после реализации:

1. Первый запуск без модели; недоступный сервер; discovery; пустой список; успешная и отменённая проверка; облачный профиль с корректной подписью передачи данных.
2. Chat: длинный потоковый ответ, stop, ручная прокрутка вверх, возврат вниз, новый/найденный/архивный разговор, copy/fork/export/delete, видимые ошибки.
3. IDE: папка и проект, файл, несколько вкладок, несохранённый черновик, поиск и быстрый переход, diff сохранения, подтверждение агента, отклонение, recovery и откат.
4. Фоновая задача: переключение разговора/режима, возвращение к ожидающему подтверждению, stop; запрет смены пространства во время выполнения.

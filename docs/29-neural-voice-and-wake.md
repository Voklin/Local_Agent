# 29. Нейроозвучка Мии и фраза активации

Версия 6.2 добавляет два независимых пути: создание русского аниме-голоса и
переключение к Мие по фразе. Нейроозвучка использует отдельный Qwen3-TTS сервер;
фраза распознаётся существующим STT (например whisper.cpp), без запроса к LLM.

## Выбор модели и установка

Выбрана официальная
[Qwen3-TTS-12Hz-1.7B-VoiceDesign](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign),
Apache-2.0. В документации Qwen заявлены русский язык и задание тембра/эмоций
описанием. Профиль «Мия, аниме на русском» задаёт молодой взрослый женский голос,
мягкий высокий тембр и выразительную доброжелательную интонацию. Это voice design
по инструкции: соответствие аниме-стилю и постоянство тембра нужно оценивать слухом.

В настройках профиля Мии выберите Qwen3-TTS. Кнопка «Открыть папку установки TTS»
открывает штатный `tools/tts` в исходниках или `resources/tts` в установщике.
Запуск и требования описаны в [инструкции sidecar](../tools/tts/README.md).
Python 3.12, отдельные PyTorch/qwen-tts зависимости и веса устанавливаются отдельно
при первом запуске скрипта; основной frozen Core их не импортирует. Загрузка
составляет несколько ГБ. На CPU синтез может быть медленным; начинайте с коротких
фраз. GPU режим требует совместимого CUDA PyTorch в отдельной среде.

В профиле: `tts_provider=qwen3`, полный `tts_url` по умолчанию
`http://127.0.0.1:9080/v1/audio/speech`, поле `tts_style`. Изменения сохраняются
через общую атомарную запись companion.json. Старые профили продолжают использовать
Windows-голоса, пока пользователь не выберет новый provider.

## От текста до звука

`bridge.voice_speak` выбирает Windows SpeechService либо
[`NeuralSpeech`](../core/python/neural_speech.py). Новый путь проверяет текст до
1200 символов, темп и громкость, создаёт sequence и worker. Async HTTPX POST содержит
`input`, `instructions`, русский язык и запрос WAV. Ответ ограничен 15 МБ и
проверяется модулем wave: PCM16 mono 8–48 kHz, до 120 секунд.

После получения Core публикует `voice_audio`. Глобальный
[`NeuralAudio`](../apps/desktop/src/NeuralAudio.tsx) играет WAV в HTMLAudioElement
с выбранными громкостью и темпом. CSP разрешает только собственные/data/blob media.
Событие окончания/ошибки возвращается через `voice:playback`. Номер sequence
проверяется, поэтому старое окончание не завершит новую озвучку. Состояния:
`synthesizing` → `speaking` → `idle` либо `error`.

Stop устанавливает Event отмены, закрывает клиентский HTTP запрос, публикует
`voice_audio_stop` и останавливает плеер. Worker ограничен deadline, не держит
bridge и не блокирует задачи/Telegram. На сервере talker forward pre-hook проверяет
закрытие клиента и deadline 150 секунд. Он прерывает генерацию перед следующим
forward; текущая операция PyTorch завершается самостоятельно. Hook и слот снимаются
в finally, поэтому отменённый запрос не продолжает держать HTTP 429 до полного
синтеза текста. Deadline проверяется на шагах, а не жёстко прерывает native-код.
В Qwen3-TTS 0.1.1 наружный `generate()` не передаёт произвольный `stopping_criteria`
в talker, поэтому используется публичный PyTorch hook без правки site-packages.

[`qwen_server.py`](../tools/tts/qwen_server.py) грузит официальный model ID,
использует `generate_voice_design(language='Russian', instruct=...)`, фиксированный
seed и ограничение 1536 токенов. Сервер принимает одну генерацию одновременно,
слушает только 127.0.0.1, отвергает браузерный Origin и не включает CORS.
Текст и аудио не сохраняются на диск. Размер JSON до 16000 байт.

## Активация по фразе

В профиле сохраняются `wake_phrase` (по умолчанию «Привет, Мия») и
`wake_auto_send` (по умолчанию выключено). Прослушивание включается отдельной
кнопкой верхней панели, действует во всех трёх режимах и не восстанавливается
автоматически после перезапуска.

[`WakeListener`](../apps/desktop/src/WakeListener.tsx) записывает фрагменты до
12 секунд или 0,8 секунды тишины после речи. `MicrophoneRecorder.hasSpeech` требует
несколько audio blocks с RMS выше порога, чтобы не отправлять тишину в STT.
Это простой speech gate, который может пропускать шум; это не обученный VAD.
Только фрагменты с обнаруженным звуком поступают в настроенный STT URL.

[`wakeCommand`](../apps/desktop/src/wakePhrase.ts) сопоставляет слова только
с начала текста, игнорируя регистр, пунктуацию фразы и различие е/ё. Команда
возвращается с исходной пунктуацией. Для разрыва фразы между фрагментами хранится
ограниченный хвост предыдущего текста. Совпадение в середине произвольного
предложения не является активацией.

После фразы окно показывается/фокусируется и открывается Мия. Команду можно сказать
в той же реплике. После отдельной фразы дождитесь индикатора «Мия активирована» и
произнесите команду в течение 15 секунд. В стандартном режиме она заполняет поле
для проверки; при включённом auto-send запускается задача Мии с обычными проверками
инструментов и diff approval. Никакого отдельного обхода разрешений нет.

На время задачи, ручной записи/транскрипции и собственной озвучки прослушивание
приостанавливается. Cleanup выключает tracks, отменяет принадлежащий слушателю STT
и не возобновляет старый цикл. Пока armed=true, Electron отключает background
throttling окна; после выключения возвращает его. Приложение должно оставаться
запущенным. Это периодический STT, задержка зависит от скорости speech-сервера.

## Проверки

### Диагностика недоступных серверов

Ошибка `ConnectError` означает отсутствие соединения с выбранным endpoint.
В проверенном локальном профиле были правильные адреса, но отсутствовали слушатели
на 8080 и 9080 и среда Qwen3-TTS. В системе был зарегистрирован только Python 3.15,
поэтому запуск через `py -3.12` тоже требовал исправления окружения.
Скрипт TTS теперь принимает `-PythonPath` для существующего Python 3.12,
`-InstallOnly` для подготовки без загрузки модели и восстанавливает недостающий
PyTorch при повторной установке. Core выдаёт отдельные инструкции для недоступных
STT/TTS вместо одного названия класса исключения; адреса с ключами не выводятся.
Опциональный `-LowMemory` выбирает BF16 на CPU; сервер сначала получает локальный
снимок модели и загружает processor из его папки. Проверен запуск из кеша с
`HF_HUB_OFFLINE=1`, включая токенизатор, который при загрузке по repo ID пытался
обращаться к API даже после скачивания весов.

Для STT установлен официальный CPU whisper.cpp b5454 с многоязычной base.
Архив и веса сверены с SHA256 поставщиков. Реальный `/health` вернул 200,
`/inference` принял синтетический PCM16 mono 16 kHz WAV и вернул JSON с текстом.
Это проверка транспорта и модели, а не оценка качества русского микрофона.

23 октября реальный Qwen3-TTS VoiceDesign на CPU BF16 синтезировал «Привет! Я Мия.»:
HTTP 200, PCM16 mono 24 kHz, 1,76 секунды аудио, 85,03 секунды генерации.
Локальный whisper.cpp вернул HTTP 200 и «Привет! Я Мия!». Оба `/health` ответили
успешно. На Ryzen 5 5600XT CPU-синтез заметно медленнее речи; BF16 сокращает память,
но не гарантирует ускорение на процессоре без нативных BF16-инструкций.
Во время проверки оставалось примерно 4,9 ГБ commit-запаса, GPU не использовался.
Скрипты повторного запуска сохранены локально в
`%LOCALAPPDATA%/LocalCodingAgent/speech/Start-STT.cmd` и `Start-TTS.cmd`;
автозапуск при входе в Windows не включён. Звук не проигрывался и микрофон
пользователя не записывался. Проверка не заменяет оценку тембра прослушиванием.

Два настоящих HTTP-теста проверяют PCM/WAV, русский язык и описание голоса,
точный playback sequence, ограничения текста и отмену зависшего синтеза менее чем
за две секунды. Двенадцать контрактов расширения проверяют совместимость профиля
Мии с прежними возможностями. GUI fixture использует синтетический микрофон,
заданный STT transcript и беззвучный WAV, без записи голоса/экрана пользователя.
Качество реального Qwen3 голоса требует запуска модели и прослушивания; протокольные
тесты не считаются такой оценкой.

### Регрессия HTTP 429 после отмены

На работающем сервере получен настоящий HTTP 429: предыдущий длинный CPU-синтез
продолжался после отключения клиента. Сервер перезапущен с проверкой отмены.
В реальной Qwen3-TTS после пяти секунд вычислений закрытие HTTP освободило слот
за 0,25 секунды. `/health` теперь сообщает `busy`. Журнал записывает тип ошибки и
HTTP-код без текста/тембра; ошибки параметров возвращают 400, deadline — 504,
непредвиденные ошибки — 500. Core различает 429/504/400/404 и не показывает тело
произвольного ответа сервера. Изменения сообщений Core попадут в приложение при
следующей сборке; перезапущенный Python TTS уже использует исправление отмены.

Семь тестов прошли: TTS HTTP/WAV/sequence, клиентская отмена, понятные HTTP ошибки,
серверные disconnect/deadline с удалением hook и успешным повтором, а также STT.
Серверные тесты используют настоящий HTTP и управляемый talker без загрузки torch.

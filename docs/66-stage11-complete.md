## Поведение в приложении

В IDE модель может вызвать `delegate_readonly` для отдельного исследования.
Это настоящий дочерний AgentEngine, а не имитация последовательности ролей.
В «Работе модели» видны дочерние исследования, их состояния и история расхода.
Результат приходит родителю как данные инструмента с путями и SHA-256 источников.
Сам по себе ответ ребёнка не подтверждает готовность основной задачи.

Родитель и ребёнок используют одну модель, адрес, API protocol и ключ из замороженного
подключения родителя. Глубина — один уровень, до трёх детей за run epoch. Права ребёнка
уже прав родителя: пересечение разрешённых `list_files`, `read_file`, `read_range`.
Запись, программы, desktop actions, MCP и вложенное делегирование недоступны.
Модель не может повысить права через JSON аргументы или неожиданный tool call.

Передача синхронная: родитель ждёт ребёнка, освободив inference lease после закрытия
своего потока. Ребёнок занимает общий FIFO scheduler и освобождает его после cleanup;
только затем родитель продолжает генерацию. Stop родителя отменяет всё дерево.
Завершение родителя как `completed` при незакрытых детях запрещено.

Handback ограничен 8000 символами и 24 источниками. Это ограничение передачи данных,
не суммарный лимит задачи. Изменение прочитанного файла, project instructions или
policy перед передачей блокирует **весь ответ**, а не только удаляет ссылку из списка.
Полный child transcript хранится отдельно в его checkpoint; каталог пользовательских
чатов им не засоряется. Удаление родительского чата убирает также child checkpoints
и журналы. Immutable artifacts сохраняются по существующей политике резервных копий.

## Ресурсный контракт

Одна process-wide группа `shared-inference`, один активный клиентский inference,
наследование подключения ребёнком и запрет разных моделей в живых фоновых owners —
явная MVP-политика. Main, child, Лола, research, probe, repair и memory используют
один арбитр. Ожидание approval не удерживает generation lease. Старое завершение
не может освободить ресурс нового owner.

Сервер с ошибкой OOM не получает повтор того же SDK запроса: задача приостанавливается
с объяснением. Generic временные сетевые ошибки сохраняют прежние bounded retries;
partial streams и неизвестные side effects не повторяются.

`managed_residency=false`: Neutral не обещает, что в VRAM находится единственная модель,
не выгружает чужие модели и не управляет внешним LM Studio/TTS/STT. Сервер может продолжать
вычисление после закрытия клиентского соединения; transport lease не является GPU fence.
Разные residency groups и автоматическое размещение разных моделей не входят в этот MVP
и не маскируются под реализованное управление памятью.

## Добровольный бюджет внешнего API

В настройках «Контекст и лимиты» появился блок «Добровольный бюджет внешнего API».
По умолчанию выключен. Пользователь задаёт сумму, валюту и цены миллиона входных/выходных
токенов. Тарифы не угадываются и не подставляются из устаревающей таблицы.

Admission выполняется **до POST**, в транзакции создания reservation. Порог охватывает
логическую задачу по chat/journal, всех детей и resume epochs: обычное продолжение
не обнуляет расход. Известный usage пересчитывается по введённым ценам, активные запросы
занимают оценочный резерв. Отмена очереди до HTTP расход не создаёт. Для HTTP без usage
сохраняется оценка; отсутствие телеметрии не считается бесплатным вызовом.

Это порог **планируемых расходов**, а не гарантия итогового счёта: input tokens могут
быть оценкой, провайдер может сообщить usage поздно или превысить резерв. После изменения
цен известные токены истории задачи пересчитываются по новой пользовательской оценке;
старые версии правил остаются у прежних runs. История показывает оценку, а не банковское
списание. Собственные/private/loopback endpoints сохраняют локальную политику без
денежного cap; через такой self-hosted URL paid gateway этим механизмом не ограничивается.

Local auto не получил новых произвольных суммарных ограничений токенов или минут.
Stop, проверки отсутствия прогресса и ограничения глубины/ширины дерева сохранены.
Диагностические тесты могут задавать собственный deadline — это не default приложения.

## Квитанции и ledger

`ToolExecutor` добавляет trusted `_receipt` и `_run_id`; поля результата MCP не могут
подменить эти значения. SQLite CallJournal сохраняет квитанцию и увеличивает epoch tool
counter в **одной транзакции** с проверкой chat/journal/run. Повтор той же квитанции не
удваивает счёт. Привязка остаётся на верхнем уровне event и при хранении крупного result
в ArtifactStore. Сбой до следующего checkpoint больше не теряет учёт инструмента.

HTTP attempts считаются транспортным hook, usage — только по доступной телеметрии,
reservations не выдаются за charge. Parent ledger — собственный расход; дочерние записи
показаны отдельно. Денежная оценка включает весь логический task journal.

PID + process creation token отличают прежнего владельца от нового процесса с тем же PID.
После kill/restart active attempts получают interrupted/unknown, reservations снимаются,
live UI owners не воскрешаются. Состояния children в checkpoint обновляются из scoped registry.
Неизвестные эффекты по-прежнему проходят CallJournal recovery, а не автоматический replay.

## Карта реализации

| Файл | Роль |
| --- | --- |
| `agent/child_executor.py` | Изолированный child engine, readonly dispatch, join, источники и свежесть handback. |
| `agent/run_registry.py` | Parent/child identities, depth/fan-out, terminal join guard, telemetry и денежный admission. |
| `agent/inference_scheduler.py` | Общая очередь, точные lease tickets, resource capability metadata. |
| `agent/run_policy.py` | Валидация порога/цен, целочисленный расчёт оценки, unknown usage и OOM. |
| `agent/call_journal.py`, `tool_executor.py` | Атомарный durable receipt + tool counter. |
| `core/python/task_execution.py` | Подключение handoff к существующему dispatch и привязка policies к run. |
| `core/python/task_service.py` | Scoped проекции фоновых owners, recovery дерева и общий shutdown. |
| `GenerationFields.tsx`, `TaskProgress.tsx`, `RunHistory.tsx` | Настройки и понятное отображение расходов/детей в текущем дизайне. |

Миграция таблиц не нужна: schema v3, дополнительные JSON поля совместимы с прежними
данными. Canonical history, TaskStore, RunState, ToolExecutor, CallJournal и policy
остаются единственными источниками соответствующего состояния.

### Живой LM Studio

Использована только Ornith 1.5 9B, context 8192, strict VRAM cap, KV CPU, eval batch 128,
Flash Attention и Q8 cache. Перед загрузкой проверено отсутствие других моделей.

- Ручной профиль: child завершился; следующий запрос родителя корректно остановлен
  до HTTP из-за обязательных схем в окне 8K. Это воспроизведение safety gate, не успешный финал.
- Local auto: **4 HTTP совпали с ledger**, child завершился, исходник не изменён,
  reservations 0. Parent final был прерван внешним deadline теста на **180.359 s**.
  Задача в целом **paused**, а не completed. Этот тест подтверждает handoff, учёт и отмену;
  не доказывает качество многофайлового кодирования этой моделью.
- Unload SDK сначала вернул timeout; последующая REST-проверка подтвердила отсутствие
  собственной тестовой модели. Чужие модели не выгружались.

Точные source hashes/параметры сохранены в `.test-data/stages11-15-live*/report.json`;
после этих измерений уточнена атомарность tool counter и проверена отдельно. Отчёты не
переписывались под новый исходный код. JSON-quality gate главы 59 остаётся отдельным.

Установщик, commit/push, merge/release и установка поверх приложения не выполнялись.
Ранее подготовленные изменения и пользовательский `docs.zip` сохранены.

# 13. Учебный маршрут и словарь

## Маршрут 1. Понять данные и функции

Прочитайте `model_preferences.py`, затем `security.py` и `tools.read_file`. Эти участки меньше основного движка и показывают аргументы, возврат словаря, исключения, работу с `Path` и проверку условия.

Упражнение: создайте учебную папку и вызовите `resolve_allowed_path` для файла внутри неё и `../outside.txt`. Объясните, почему проверяется результат `resolve`, а не просто наличие подстроки `..`. Затем найдите тест, который проверяет тот же инвариант.

Критерий понимания: вы можете объяснить, какие значения возвращает функция, в каком случае выбрасывает исключение и какие побочные действия выполняет.

## Маршрут 2. Изучить классы и состояние

Прочитайте `PlanStage`, `TaskPlanner`, затем `TaskService.__init__` и `select_chat`. Нарисуйте, какие данные относятся к одному чату, одному запуску и всему процессу.

Упражнение: на копии тестового JSON измените статус задачи на `running`, затем изучите сценарий открытия чата после аварии. Почему сервис переводит его в `paused`, а не обещает, что старый поток продолжает выполняться?

Критерий понимания: вы различаете экземпляр класса, JSON-запись и уже не существующий процесс.

## Маршрут 3. Пройти через UI

Изучите `main.tsx`, одну форму в `App.tsx`, `useState` и `useEffect`, затем preload API. Проследите `getModelSettings` через все четыре слоя до Python.

Упражнение: добавьте в учебной ветке поясняющую подпись к полю модели, выполните `npm run typecheck` и `npm run build`. Опишите, что проверила каждая команда и чего она не проверила.

Критерий понимания: вы можете отличить рендер React от сетевого запроса и от файловой записи.

## Маршрут 4. Разобраться в асинхронности

Прочитайте `ModelStream`, `ModelClient.submit`, `result`, `cancel`, а затем `test_streaming.py`. Обратите внимание на две разновидности future и на то, что очередь имеет максимальный размер.

Упражнение: объясните отдельно остановку до HTTP-заголовков и после первого текстового чанка. Покажите, где выставляется флаг, где отменяется корутина и где серверная фикстура обнаруживает закрытие сокета.

Критерий понимания: вы не смешиваете «UI перестал ждать» и «сетевое соединение реально закрыто».

## Маршрут 5. Изучить агентный цикл

Только после предыдущих шагов прочитайте `AgentEngine.run`. Разбейте его на построение контекста, генерацию, сбор tool calls, исполнение, повтор и завершение.

Упражнение: по учебному transcript вручную сопоставьте assistant `tool_calls[0].id` с `tool_call_id` результата. Затем покажите, почему незавершённые JSON-аргументы нельзя исполнять сразу после первого чанка.

Критерий понимания: вы можете объяснить, как модель выбирает действие, но приложение сохраняет контроль над его исполнением.

## Маршрут 6. Научиться сопровождению

Изучите один маленький diff в Git, описание PR и `validate.yml`. Затем измените аннотацию символа и пересоздайте справочник. Это связывает код, документацию и проверку в одно изменение.

Упражнение: найдите ограничение из главы 11 и предложите тест, который должен падать до исправления. Само исправление не обязательно делать сразу; сначала сформулируйте наблюдаемое требование.

## Словарь

| Термин | Значение в проекте |
| --- | --- |
| Агент | Цикл модели и инструментов с состоянием и правилами приложения |
| Модель | Генератор ответов на внешнем/локальном HTTP-сервере |
| Provider / endpoint | Адрес и параметры доступа к совместимому API |
| Prompt | Пользовательский запрос; system prompt отдельно задаёт правила модели |
| Tool call | Предложение модели вызвать функцию с JSON-аргументами |
| Tool result | Фактический ответ исполнителя, связанный с `tool_call_id` |
| Transcript | Последовательность сообщений диалога |
| Working context | Выбранная часть данных, отправляемая в очередной запрос модели |
| Project memory | Компактные структурированные сведения между задачами |
| Checkpoint | Запись статуса и шага для восстановления задачи |
| Resume | Новый запуск с сохранённой задачей и историей, не продолжение старого сокета |
| Diff | Сравнение старого и предлагаемого текста |
| Approval | Явное решение пользователя по предложенной операции |
| UUID | Случайный идентификатор чата, запуска или подтверждения |
| Hash | Детерминированный отпечаток данных; здесь также имя служебного файла |
| Atomic replace | Замена целевого файла подготовленным временным файлом |
| Race condition | Ошибка, зависящая от порядка конкурентных действий |
| Process | Отдельная программа с собственной памятью |
| Thread | Поток выполнения внутри процесса с общей памятью |
| Event loop | Цикл исполнения ожидающих async-задач |
| Coroutine | Приостанавливаемая async-функция |
| Future | Объект будущего результата вычисления |
| Backpressure | Ограничение producer, когда потребитель не успевает |
| SSE / chunk | Поток серверных событий / один фрагмент ответа |
| JSON-lines | Один JSON-объект на строку stdio-протокола |
| IPC | Обмен между процессами Electron через фиксированные каналы |
| Main / renderer / preload | Управляющий процесс, UI-страница, ограниченный мост Electron |
| Hook | Механизм React для состояния, эффекта или ref |
| Closure | Функция вместе с захваченными переменными окружения |
| HMR | Обновление UI-модулей при разработке без полной перезагрузки |
| Bundle | Собранные JS/CSS-ресурсы для выполнения |
| Workspace | Подпроект npm, связанный с корневым package |
| Lock-файл | Фиксация конкретного дерева зависимостей |
| Fixture | Контролируемое окружение/данные для теста |
| Smoke test | Проверка основного сквозного сценария |
| CI | Автоматические проверки на отдельной машине |
| AST | Синтаксическое дерево; используется для каталога объявлений |
| Legacy | Сохранённый предыдущий путь с собственными особенностями |
| Scaffold / заготовка | Структура для будущей функции без всей рабочей интеграции |

## Проверочные вопросы

Почему `overwrite=true` не даёт разрешения на запись? Почему одна UI-кнопка требует изменений в нескольких файлах? Где хранится код прочитанного моделью файла? Чем `TaskService` отличается от `AgentEngine`? Какие классы не подключены к Electron? Почему 60 успешных тестов не доказывают качество каждого ответа модели?

Ответы находятся в главах 3, 5, 8–11. Если вы можете показать конкретные участки исходников, а не только повторить определения, вы уже понимаете архитектуру проекта на практическом уровне.

# Мия: Serena и анимации персонажа, 6.4

## Что видит пользователь

Основной вариант озвучки — «Мия · Serena — рекомендуется». Модель работает на CPU.
При открытии режима Ассистент приложение пытается запустить локальный Piper;
перед озвучиванием запуск проверяется повторно. Есть состояние подключения,
кнопки «Запустить Serena»/«Проверить подключение» и «Послушать голос».
Скорость и громкость отображаются в процентах. Ответы можно озвучивать автоматически.
Системные голоса Windows и внешний HTTP/Qwen сервер остаются отдельными вариантами.
Технический ID нейроголоса не показывается; адрес и установка вынесены в
дополнительные параметры профиля. При смене движка профиль сохраняется сразу;
изменённые скорость/громкость сохраняются кнопкой «Сохранить голос».

Serena — пробная модель из [процесса обучения](SERENA_TRAINING_PLAN.md), с его
известными несовершенствами произношения. Установка интерфейса не улучшает веса модели.
ONNX 63 516 051 байт, SHA256
`4610a755335a68bb102ea0bde426aa95f75191e8d6d438d8a51d99397319913d`.

## Запуск и границы управления

`SpeechRuntime` находится в `apps/desktop/electron/speechRuntime.ts`, работает
только в main процессе Electron и не принимает от renderer команды или EXE пути.

| Метод | Назначение |
| --- | --- |
| constructor | Получает фиксированные пути локального runtime, серверных скриптов и кандидата модели. |
| files | Строит пути Python, ONNX и piper_server.py; не использует ввод из чата. |
| install | Проверяет размер/хеш ONNX и русский JSON 22050 Гц, копирует модель в локальную папку приложения. |
| status | Проверяет фиксированный localhost:9080/health с таймаутом, наличие модели/runtime и принадлежность процесса. |
| start | Объединяет параллельные запросы запуска в одну Promise. |
| launch | Использует готовый runtime, при необходимости устанавливает модель из локального кандидата, запускает Python без shell и ждёт health. |
| stop | Останавливает только собственный PID/tree; уже работающий внешний сервер не завершает. |

Пути на Windows: `%LOCALAPPDATA%/LocalCodingAgent/piper-runtime/Scripts/python.exe`
и `%LOCALAPPDATA%/LocalCodingAgent/speech/piper/serena/ru_RU-miya-serena-medium.onnx`.
В режиме разработки кандидат берётся из `artifacts/voice/serena-piper/`.
Для установленного приложения с отсутствующей моделью можно выбрать ONNX через
системный диалог «Указать файлы Serena»; JSON должен лежать рядом. Подмена другой
моделью не проходит проверку SHA256. При отсутствии Python/Piper показывается
инструкция установки компонентов. В этой локальной версии они уже установлены.
В установщик не включаются Torch/Qwen, training checkpoints или синтетический датасет.

IPC `voice:runtime` допускает только status/start/stop/install и проверяет sender
так же, как остальные обработчики. Импорт использует native file picker.
`preload.speechRuntime` и vite-env.d.ts описывают эти операции. При закрытии
приложения собственный Python процесс завершается; выбор Windows освобождает
управляемый Piper. Порт, занятый другой моделью, даёт понятную ошибку.

## Профиль и воспроизведение

`agent/companion_preferences.py` принимает новый provider `piper` и выбирает его
для новых профилей. Core bridge маршрутизирует Piper и Qwen в общий NeuralSpeech.
`NeuralSpeech.status(provider)` возвращает понятное имя Serena при том же внутреннем
ID `miya-anime-ru`; HTTP по-прежнему возвращает PCM16 mono WAV. Прежние сообщения
отмены, sequence и подтверждение Audio player сохраняются. Ошибка соединения Piper
предлагает кнопку запуска, а не технический traceback. Обязательная запись/STT и
отправка команд по нажатию сохраняются; новая графика не включает микрофон сама.

## Персонаж и анимация

Из пользовательского изображения создан отдельный прозрачный атлас, 1774×887,
восемь ячеек 4×2. Референс использован для внешности персонажа: светлые волосы,
голубые глаза, чёрно-белая форма горничной, головной убор и серьги.
Файл находится в `apps/desktop/src/assets/miya-states.png` и импортируется Vite.
Полный prompt и cleanup prompt сохранены в `miya-states.prompt.md` рядом с ним.
Использован встроенный image_gen, без внешнего CLI/API ключей. Это набор 2D поз с
CSS анимацией, не Live2D/3D rig. Генерировалась взрослая героиня без сексуализации.

`MiyaAvatar` выбирает ячейку и доступную подпись состояния. `VoicePanel` определяет
состояние по реальному recording/transcribing, busy, tool_activity и voice status.
`App` передаёт task snapshot. Смена позы не требует обращения к модели.

| Состояние | Событие и движение |
| --- | --- |
| Ожидание | Спокойная поза, лёгкое дыхание. |
| Слушает | Запись микрофона или активный WakeListener, рука у уха и пульсация. |
| Думает | Ожидание ответа/распознавание/синтез WAV, задумчивая поза. |
| Работает | Running/applying/awaiting_approval инструмента, поза с блокнотом. |
| Говорит | Состояние speech speaking, чередование двух одинаковых поз с открытым/закрытым ртом и волна. |
| Успех | Completed задачи, улыбка/поклон на четыре секунды. |
| Ошибка | Ошибка озвучки или failed задачи, обеспокоенная поза. |

Волна — индикатор состояния, не анализ громкости аудио; рот переключается по
таймеру, точной фонемной синхронизации нет. WakeListener сообщает фоновое слушание
через локальное событие miya-listening. Переключатель анимации сохраняется в
localStorage, системный prefers-reduced-motion отключает движение независимо от него.

## Проверки

20 целевых Python тестов озвучки, отмены, профиля и расширений прошли. TypeScript,
Vite и Electron main/preload собраны. Настоящий SpeechRuntime установил проверенную
Serena, запустил её, получил RIFF WAV и остановил только собственный процесс.
Полный Electron smoke прошёл с редактором, approvals, streaming, микрофоном,
нейро-WAV и wake phrase; дополнительно проверены карточка Piper, подключение,
отсутствие технического voice ID и переключатель анимации. Скриншот:
`.test-data/electron-smoke/serena.png`. GUI использует фиктивный runtime status,
чтобы не запускать чужой Python в изолированной тестовой папке; реальный host
проверен отдельно. Записи и воспроизведение в тестах не отправлялись на колонки.

Собранный Windows 6.4.0 также прошёл два запуска со встроенным frozen Core,
очищенным PATH, сохранением профиля и корректным выходом. Новый профиль выбирает
Piper; проверка каталога Windows выполняется после явного выбора этого движка.

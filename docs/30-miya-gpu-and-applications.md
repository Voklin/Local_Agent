# 30. Мия 6.3: ускорение GPU, приложения и поиск

## Изменения и окружение

Qwen3-TTS VoiceDesign перенесена с CPU на RTX 5070. Добавлены инструменты
`list_applications/open_application`, выбор разрешённых EXE в UI, резервный поиск
и инструкции Мие выполнять эти действия напрямую. Установщик 6.3 содержит новые
UI, Core и speech-скрипты. PyTorch и веса остаются в отдельной пользовательской среде.

В `%LOCALAPPDATA%/LocalCodingAgent/tts-runtime`: Python 3.12, `torch==2.11.0+cu128`,
`torchaudio==2.11.0+cu128`, `qwen-tts==0.1.1`. Команда `start-tts.ps1 -Device cuda`
проверяет CUDA и при необходимости устанавливает согласованную пару библиотек
из официального индекса CUDA 12.8. Отдельный CUDA Toolkit не устанавливался.
CPU и `-LowMemory` сохраняются. Режим auto использует уже доступный CUDA runtime.

На GPU выбраны BF16 и SDPA. Перед загрузкой проверяются CUDA, минимум 6 ГиБ
свободной VRAM и пробная операция на устройстве. `/health` сообщает `device/busy`.
Порог не резервирует VRAM от других приложений. Модели LM Studio сервер не выгружает.
Снимок модели работает с `HF_HUB_OFFLINE=1`; пользовательский `speech/Start-TTS.cmd`
теперь запускает CUDA. STT остаётся на CPU, автозапуск Windows не включался.

## Функции и классы приложений

[`desktopApps.ts`](../apps/desktop/electron/desktopApps.ts) содержит
`DesktopApplications`, отделяющий исполняемые пути от аргументов модели.

| Метод | Назначение |
| --- | --- |
| constructor | Получает каталог userData и функции запуска/браузера от main process |
| custom | Читает до 30 JSON-записей, проверяет ID, имя и локальный абсолютный EXE-путь |
| catalog | Объединяет существующие системные EXE и пользовательские разрешения |
| list | Возвращает ID, имя и признак пользовательского разрешения без пути |
| save | Пишет временный JSON со случайным именем, затем переименовывает |
| add | Проверяет выбранный вручную существующий EXE, исключает дубли, создаёт UUID |
| remove | Удаляет пользовательское разрешение, сохраняя остальные |
| open | Сверяет ID с актуальным каталогом и запускает разрешённую функцию |

`main.ts` использует `spawn(file, [], {shell:false})`. Приложение не закрывается
при выходе агента; результат подтверждает запуск, а не управление окнами.
Браузер открывает фиксированный HTTPS Bing. `desktopRequest` обслуживает Core,
а отдельные UI IPC позволяют выбрать EXE или убрать разрешение. Модель не получает
этих IPC. Проверка источника IPC сохраняется. Добавление доступно вне задачи.

`ConnectionsSettings.tsx/changeApplication` показывает список, вызывает picker
или удаление, обновляет состояние и ошибки. `preload.ts` и `vite-env.d.ts` задают
фиксированный контракт. Core `desktop_service.py` принимает только ID без путей,
команд и аргументов; общий PC-tools toggle действует на запуск. Уже существующий
dispatch `task_service.py` подключает PC tools к Мие, Chat и IDE, включая JSON tool
calling. `engine.py` объясняет последовательность list → open и прямой поиск.

## Поиск и проверки

`browser_search` открывает Bing. `search_web` отдельно получает DuckDuckGo HTML
и при отказе использует Bing RSS. В реальном окружении DuckDuckGo дал TLS-таймаут,
Bing ответил HTTP 200, но вернул нерелевантную ссылку. Результаты без совпадений
со словами запроса теперь отбрасываются; фильтр не гарантирует смысловую релевантность.
Если выдача недоступна, инструмент сообщает `content_available:false`, а не
утверждает, что информация прочитана. Полные страницы не читаются. Ограничения
объёма, XML и URL: [глава 27](27-desktop-and-telegram.md).

Node-тест каталога проверяет ID, запрет команд/путей, отсутствие аргументов, EXE,
дубли, удаление и браузер без открытия реальных приложений. Python-контракты
проверяют broker, выключатель/отмену, резервный поиск и фильтрацию ссылок/выдачи.
Electron smoke прошёл с настоящими main/preload/renderer/Core и fixture picker,
включая добавление, чтение и удаление разрешения. Frozen Core прошёл 15 проверок.

Установщик: `artifacts/windows/LocalAgent-6.3.0-setup-x64.exe`, 164334976 байт.
SHA256: `e63f6f4edcc06e96a9ae10e35a1010470e5a76519c4d8375d5fe13530af7acbf`.
Готовое `win-unpacked/LocalAgent.exe` дважды прошло packaged smoke с очищенным PATH
и отсутствующим внешним Python, включая каталог приложений и восстановление настроек.
19 целевых Python-тестов и Node-тест каталога прошли. Для локальных HTTP-тестов
потребовался запуск вне сетевой песочницы Windows (внутри был WinError 10013).
Приложение пользователя автоматически не переустанавливалось; GitHub Release
в этом этапе не создавался. Инсталлятор можно установить поверх предыдущей версии.

Зависимости: [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS),
[официальные CUDA wheels PyTorch](https://pytorch.org/get-started/previous-versions/).

## Проба Qwen 0.6B CustomVoice и Ono_Anna, 23 октября

Пользователь выбрал готовый голос Ono_Anna. В сервер добавлены `--model`
(`voicedesign-1.7b` или `custom-0.6b`) и `--speaker`; PowerShell передаёт их через
`-Model`/`-Speaker`. По умолчанию исходный скрипт сохраняет VoiceDesign 1.7B.
На этом ПК существующий `speech/Start-TTS.ps1` теперь запускает `custom-0.6b`
с `Ono_Anna` на CUDA, а прежний запуск сохранён в `Start-TTS-VoiceDesign.ps1`.
Оба файла находятся в `%LOCALAPPDATA%/LocalCodingAgent/speech`.

`main` загружает официальный `Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice` локально,
проверяет минимум 3 ГиБ свободной VRAM и записывает выбранный speaker в модель.
`synthesize` вызывает `generate_custom_voice` с Russian и готовым speaker;
описание тембра профиля в этой ветке не передаётся. Для VoiceDesign остаётся
`generate_voice_design` с описанием. HTTP API, формат WAV, отмена и таймаут общие.
`GET /health` показывает действительные model, speaker и device.

Измерение на RTX 5070, BF16/SDPA, seed 42; время включает HTTP до готового WAV,
но не обратное распознавание. Воспроизведение и микрофон не включались.

| Запрос | Генерация | Длительность WAV | Общая VRAM после запроса |
| --- | --- | --- | --- |
| «Привет! Я Мия.», первый | 27,78 с | 3,68 с | 7298 МиБ |
| Та же фраза, повтор | 11,38 с | 3,68 с | 7308 МиБ |
| Приветствие с предложением открыть приложение/найти информацию | 27,81 с | 9,44 с | 7542 МиБ |

Непосредственно до остановки 1.7B было занято 9451 МиБ, после остановки 5132 МиБ,
после длинного запроса 0.6B — 7542 МиБ. Это снимки общей VRAM с другими
приложениями, не точный максимум памяти одного процесса. Снижение относительно
предыдущего сервера — примерно 1,9 ГиБ. Предыдущий прогретый замер 1.7B давал
5,55 с на 1,76 с звука: текущие результаты не доказывают ускорения генерации
секунды звука (около 3 с вычислений на 1 с речи у обеих моделей). Голос 0.6B
произносит короткую фразу дольше; субъективную аниме-интонацию оценивает пользователь.

Все три PCM16 mono WAV приняты whisper.cpp, текст распознан по-русски без потери
смысла. Два HTTP-теста отмены/deadline прошли. Образец длинной фразы сохранён в
`artifacts/voice/miya-ono-anna-ru.wav`, журнал — `.test-data/qwen06-benchmark.json`.
Сервер оставлен работающим на прежнем URL; параметры приложения менять не требуется.
Инсталлятор 6.3 и GitHub в рамках этой пробы не обновлялись.

## Проба Piper Irina на CPU, 23 октября

По запросу пользователя установлен `piper-tts 1.8.0` с CPU `onnxruntime 1.31.0`
в отдельную среду `LocalCodingAgent/piper-runtime`. Русский ONNX голос Irina medium
скачан с `rhasspy/piper-voices` вместе с JSON и MODEL_CARD; размер 63 201 294 байта,
SHA256 `8ff38212d23da300bbe3705c645e6e5b9475f0bfde01558eb17813e22acaaaaa`.
Модель не переобучалась, высота/скорость голоса искусственно не изменялись.

Новый `tools/tts/piper_server.py` загружает `PiperVoice.load(use_cuda=False)`.
`main` подключает callback `server.synthesize` к прежнему localhost Handler.
`synthesize` собирает PCM16 mono чанки, проверяет формат/120 секунд/15 МиБ и
закрытие клиента между предложениями, затем создаёт WAV стандартным модулем wave.
Сборка WAV происходит после успешного сбора чанков, чтобы отмена до первого чанка
не подменялась ошибкой незаполненного WAV-заголовка. Общий Handler сохраняет
JSON/Origin/размер запроса, единственный слот, HTTP-коды и deadline 150 секунд.
Ветка Qwen сохраняет talker hook. В Core и Electron изменений для этой пробы нет.

`tools/tts/start-piper.ps1` создаёт Python среду при необходимости, проверяет наличие
ONNX/JSON, устанавливает Piper при отсутствующем импорте и запускает сервер.
На этом ПК обычный `speech/Start-TTS.cmd` теперь вызывает этот скрипт;
прежний Qwen 0.6B запуск сохранён в `speech/Start-TTS-Qwen-OnoAnna.ps1`.

| Запрос после окончательного перезапуска | HTTP до готового WAV | Звук |
| --- | --- | --- |
| «Привет! Я Мия.», первый | 0,17 с | 2,17 с |
| Та же фраза, повтор | 0,08 с | 2,12 с |
| То же длинное приветствие, что у Qwen | 0,34 с | 7,63 с |

На самом первом запуске фонемизатора первый запрос занимал 2,06 с; после прогрева
в первом цикле было 0,08 с и 0,25 с для короткого/длинного примеров. Это измерения
готового WAV, без времени STT/воспроизведения. Процесс после первого цикла занимал
около 238 МиБ working set; файлы среды и модели в эту цифру не входят.
Piper использует CPUExecutionProvider и не загружает модель в видеопамять.
Общая VRAM после остановки Qwen уменьшилась примерно с 7542 до 5000 МиБ
(снимки с другими приложениями, не изолированное измерение одного процесса).

Все три примера в обоих циклах приняты локальным STT, смысл распознан; в финальном
длинном примере STT записал «бравзере» вместо «браузере». Субъективную естественность
и соответствие аниме-персонажу оценивает пользователь. Образец:
`artifacts/voice/miya-piper-irina-ru.wav`; замеры `.test-data/piper-benchmark.json`.
Три HTTP/adapter теста прошли: отмена Qwen, deadline, Piper callback/WAV/disconnect.
Подробная установка и условия лицензий: [инструкция TTS](../tools/tts/README.md).
Инсталлятор/GitHub на этом шаге не обновлялись.

## Сторонний femaleyoungeager и возможность собственного голоса

По запросу пользователя проверен `femaleyoungeager` из
[Mantella RU Piper 1.0](https://github.com/ronanime-arch/mantella-ru-piper/releases/tag/v1.0).
Из архива размером 1 289 432 016 байт получены только два нужных файла через
HTTP Range и центральный каталог ZIP: фактически скачано 58 616 012 байт.
ZIP CRC проверен при чтении. Вычисленные SHA256 (не отдельная подпись автора):

- ONNX, 63 516 051 байт: `943c1086dd3d66a30228789ec6a7d02dda3f2b0461f6164a99b649b296fc0c44`.
- JSON, 4880 байт: `62f794db326aad1d936ddbc9e5a6388a8c39baa483ca9d813b2f98c124ac9837`.

Голос проверялся на временном порту 9081. Первый короткий запрос: 0,14 с / 1,68 с
звука; повтор: 0,06 с / 1,44 с; длинный пример: 0,20 с / 5,86 с. Формат PCM16
mono принят, но STT вместо «Я Мия, твоя помощница» записал «Я не твоя помощница»;
в коротких примерах имя тоже распознавалось неверно, в длинном были ошибки слов.
Эти ошибки не являются оценкой тембра человеком, но выявляют риск разборчивости.
Проверены язык `ru`, частота 22050 Гц и карта phoneme_id_map: относительно Irina
нет пропавших ключей или изменённых ID, поэтому простого исправления карты нет.

Образец сохранён в `artifacts/voice/miya-piper-femaleyoungeager-ru.wav`;
измерения в `.test-data/piper-young-benchmark.json`. Временный сервер остановлен,
основной порт 9080 и обычный запуск оставлены с Irina до оценки записи пользователем.
Голос основан на русской озвучке Skyrim; автор набора обозначает некоммерческое
распространение. Модель не включалась в установщик или GitHub проекта.

Собственный голос Piper технически возможен. Рекомендуемый путь — дообучение
готового training checkpoint `.ckpt`, а затем экспорт в ONNX и соответствующий
JSON; одного готового ONNX недостаточно для штатного продолжения обучения.
Нужны чистые записи одного согласованного тембра и точные тексты каждой фразы.
Для Мии можно подготовить синтетический датасет понравившимся TTS, проверив
произношение/постоянство голоса и условия использования исходной модели.
Piper будет приближать выбранную манеру; полное сохранение эмоций не гарантируется.
Подготовка данных и обучение пока не выполнялись: источник голоса не выбран.
Процесс обучения и экспорт описаны в [официальной инструкции](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/TRAINING.md).

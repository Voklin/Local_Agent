# Этап 10: JSON compatibility на реальной локальной модели

27 октября 2026. Основание — [Roadmap V2](57-roadmap-v2.md) и
[baseline 20a](58-agent-baseline-20a.md). Изменения касаются текстового протокола
инструментов; native calling, разрешения и verifier не заменяются.

## Что изменилось

[json_tools.py](../agent/json_tools.py) теперь запрашивает единый
`neutral.action.v1` на каждом ответе JSON-модели. Есть два вида сообщения:

```json
{"protocol":"neutral.action.v1","kind":"tool","name":"read_file","arguments":{"path":"README.md"}}
```

```json
{"protocol":"neutral.action.v1","kind":"final","text":"Ответ пользователю"}
```

Приложение снимает оболочку final перед показом/озвучиванием, а tool передаёт
обычному ToolExecutor. Схемы представлены компактным списком name/description/
parameters без лишнего API wrapper. Исторический одиночный вызов приводится к
тому же виду. Старые целые JSON envelopes остаются читаемыми для совместимости.
Parser не ищет команды внутри пояснений, цитат и примеров.

В JSON-каталоге для базового `search_text` доступны query/path; optional
pattern/case_sensitive/limit/max_depth не предлагаются малой модели. У `patch_file`
не предлагается optional expected_sha256: Qwen неоднократно выдумывала его вместо
использования возвращённой ревизии. Required поля остаются, custom/MCP schemas не
сокращаются. Исходные схемы/настройки не изменяются; native сохраняет полный набор.
Executor по-прежнему проверяет актуальность файла и согласие до записи.

Если завершённый ответ не соответствует протоколу, JsonToolStream просит модель
сформировать ответ заново. Максимум **два исправления на один логический ответ**.
Пользовательские лимиты всей локальной задачи от этого не меняются. Исходный
отклонённый ответ не исполняется; в ремонтный запрос попадает до 4000 его символов.
Последующие ошибки инструментов по-прежнему обрабатывает общий loop/progress guard.

[ModelClient._repair_json](../agent/model_client.py) пропускает каждый такой запрос
через существующий RequestBudget.fit/check, сохраняет canonical history, учитывает
дополнительные requests/usage и проверяет Stop. Счётчик `usage.json_repairs` виден
в сохранённом task snapshot. Это отдельная генерация, а не автоматическое исполнение
извлечённого JSON. Транспортные retries остаются собственной ограниченной политикой.

Ответ без подтверждённого finish, length, отказ, отмена или ошибка транспорта
не запускают протокольный repair. Частичные данные идут в прежний terminal-outcome
контракт. Объём одного ответа ограничен 1 MB. После исчерпания исправлений задача
получает ошибку с объяснением, что непринятые вызовы не исполнялись.

Даже принятый JSON ещё проходит схему аргументов, доступ, revision, preview и
пользовательское approval. Неизвестные эффекты уже исполненных операций не
повторяются этим механизмом. JSON-протокол не гарантирует правильность выбранного
инструмента, аргументов или результата задачи.

## Выбор в интерфейсе

Настройки → Модели → Протокол инструментов → «JSON в тексте · Qwen 2.5 Coder».
Режим задаётся существующим `tool_protocol=json`, без нового обязательного поля.
Chat без инструментов и служебные non-stream проверки не переводятся на action
envelope. Загруженной моделью и её памятью протокол самостоятельно не управляет.

## Проверки и статус

[test_json_compatibility.py](../tests/test_json_compatibility.py) проверяет bounded
repair, отсутствие исполнения префикса batch, невалидное имя инструмента, сохранение
required/none, EOF/length/refusal, отмену и настоящий SSE transport. Проверка Engine
отклоняет исправленную запись через approval и подтверждает неизменность файла.

Финальный unit-набор: **369 тестов OK, один Windows skip**. Включены budget/Stop
перед repair, сохранение required/custom схем и строгая граница номера строки в
oracle. Связанный набор JSON/budget — 38 тестов OK. Отдельный HTTP fixture обновлён
под final envelope; legacy tool envelopes по-прежнему проверяются, итог показывается
человеческим текстом, число ответов остаётся ровно три без лишних repair.
Итоговый HTTP/Core suite: **81 тест OK**. Документация: 78 Markdown-файлов,
3161 локальная ссылка, справочники актуальны; `git diff --check` без ошибок.
Typecheck/GUI не повторялись: UI и TypeScript этим пакетом не менялись. Установщик
не собирался; commit/push этим пакетом не выполнялись, прежние изменения сохранены.

Реальные прогоны Qwen выполнены последовательно с одинаковыми весами/load config,
seed, заданиями и контрольными лимитами. Исходные отчёты не перезаписывались:

| Версия | Размеры / сценарии | Task correct / E2E | POST | Wall time |
| --- | --- | ---: | ---: | ---: |
| Исходный baseline | small/medium/large, 15 | 1/15 | 51 | 137,932 с |
| v1: action envelope + repair | small/medium/large, 15 | 0/15 | 87 | 160,923 с |
| v2: дополнительные hints | small, 5 | 0/5 | 24 | 50,314 с |
| v3: компактные core schemas | small, 5 | 1/5 | 20 | 32,706 с |

Каталоги: `.test-data/qwen25-baseline-json-v1/`,
`.test-data/qwen25-json-stage10-v1/`, `.test-data/qwen25-json-stage10-v2/`,
`.test-data/qwen25-json-stage10-v3/`, `.test-data/qwen25-json-stage10-final15/`.
В каждом есть snapshot, hashes, raw transcripts, проверка diff и human report.md.
Финальная матрица дала 2/15 против 1/15 baseline; один trial на сценарий не доказывает
статистически значимого улучшения. На совпадающем small baseline тоже было 1/5.
Сводка всех версий: `.test-data/agent-stage10-summary.json` и
`.test-data/agent-baseline-20a-summary.md`.

В v3 все 20 POST вернули usage (добавленный счётчик repair: 0): модель следовала
формату без исправления синтаксиса. Это не приёмка решения. Ошибки v3: `**/*` вместо
пути папки; выдуманное выражение в search query и остановка ProgressGuard; при
переименовании пропущен import. Oracle отклонил незавершённые изменения несмотря
на текст «выполнено». Полноценное восстановление задачи этим прогоном не доказано.

В финальной 15-сценарной матрице: 52 выданных tool calls, 60 POST, reported usage
130828 input / 2715 output tokens, 60 reported responses, protocol repairs=0.
Repair подтверждён детерминированным настоящим HTTP/Engine тестом, но в этом
реальном прогоне не потребовался. Успешны два references-сценария; этого недостаточно
для приёмки кодовых задач. Независимый поздний аудит точных path:line не изменил
ни один прежний PASS; исходные raw JSON не правились ради нового oracle.

**Статус:** поставлена инфраструктура единого preset и bounded repair; качество
агентской работы Qwen2.5-Coder 7B пока недостаточно, gate надёжности не закрыт.
Не нужны новые глобальные лимиты: следующий шаг — проверяемый retrieval/ContextPack
и работа с evidence/завершением, затем повтор той же матрицы. Prompt-only tuning
не считается достаточным решением. Индекс/ContextPack этим этапом не реализованы.


## Контроль ContextPack 14a

В дополнительной паре из пяти small synthetic задач Qwen 2.5 Coder 7B JSON
показала 1/5 E2E без auto ContextPack и 0/5 с ним; HTTP попытки 22 → 28.
Это не пересмотр прежнего baseline 15 задач: новая отдельная контрольная пара,
те же held-out критерии. Дополнительный context не закрыл gate и дал регрессию,
поэтому автоматический ContextPack для JSON protocol по умолчанию отключён.
Точные snapshots, ограничения эксперимента и native сравнение — в
[главе 62](62-context-pack.md). Нативные функции и обычные JSON tools не отключены.

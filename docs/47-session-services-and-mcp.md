# Этап 7: сессии, протокол и общий жизненный цикл

Этап сохраняет оформление Neutral и права предыдущих этапов. Он разделяет владение
состоянием, устраняет конкуренцию тяжёлых запросов и повторную инициализацию MCP.

## Как проходит запрос

Renderer создаёт `run_id` до IPC. Общие типы в `apps/desktop/shared/` описывают
start/approve/recovery/snapshots и критические события. Electron отправляет версию 1;
Core проверяет envelope, ID, mode, решения и строгие boolean до dispatch.
Для старых локальных Python-клиентов отсутствие версии означает v1; Electron требует
явную версию в ответах. Это не полная схема всех исторических settings API: часть
некритических форм пока использует старые словари.

`SessionService` владеет выбранными chat/project, индексированным каталогом,
переименованием, переносом и восстановлением canonical history. `TaskService`
сохраняет совместимые методы-адаптеры и отвечает за исполнение/approval.
`useTaskSession` владеет состоянием сообщений и активной задачи в React.
Чужие run/chat events, запоздалый `task_end` и текст после завершения игнорируются.
Telegram передаёт один и тот же заранее выбранный run ID в уведомлении и запуске.

## Отмена и ресурсный предел

`OperationContext` совместим с Event: сигнал, monotonic deadline, `remaining`,
дочерний контекст. Отмена родителя и его более ранний срок ограничивают ребёнка.
Engine использует этот контекст вместе с существующим runtime timer.

`InferenceGate` выдаёт lease одной тяжёлой операции. Probe и задача используют один
gate; отмена сигнализирует, но не освобождает слот до завершения worker. Старый
lease не может освободить нового владельца. Это ограничение HTTP inference Neutral,
а не глобальная блокировка видеокарты или других приложений. STT/TTS остаются
отдельными службами. IPC timeout вызывает соответствующую отмену поиска, STT,
probe/discovery или задачи; потенциальные файловые effects автоматически не повторяются.

Режимные capability profiles только сужают включённые расширения. IDE получает
проект/команды при выбранной папке, Chat и Лола не получают эти группы. Явные
выключения tools, readonly и подтверждения продолжают действовать.

## MCP-соединения

`MCPSessionPool` держит до четырёх actors. Один actor в одной asyncio task открывает
SDK transport, последовательно обслуживает очередь и закрывает контекст — это
существенно для AnyIO cancel scopes. Ключ включает endpoint/command/args/timeout
и хеш token, но не название или загруженный каталог. Секреты не выдаются в status.

Транспорт переиспользуется между discovery и calls и закрывается после 45 секунд
простоя, изменения endpoint/token, выключения подключения, отмены или shutdown.
В настройках MCP показан счётчик и кнопка закрытия соединений. Отмена во время
connect тоже наблюдается; отменённая очередь не выполняется позднее. Неопределённый
результат MCP effect остаётся `OUTCOME_UNKNOWN`, повторного вызова нет.

Владелец `ExtensionService` обязан вызвать `shutdown()` перед удалением каталога:
живое stdio-подключение закономерно держит журнал открытым.

## Проверки

307 unit-тестов прошли (один Windows symlink privilege skip), включая 7 новых
контрактов: deadlines, stale lease, строгий protocol, capability scopes, общий
gate probe/task, настоящий PID reuse/invalidate и отмена connect. 79 HTTP/SSE/Core
проверок прошли. `npm run build` прошёл. Neutral Electron smoke проверил настройки
MCP, обычные IDE/approval/recovery пути и отбрасывание старых событий/позднего текста.
Совместимый editor/voice smoke тоже прошёл: editor, approvals, streaming, voice profiles,
локальное воспроизведение WAV и wake phrase из Chat.

Полный перечень файлов, методов, типов и тестов находится в
[справочниках](reference/file-map.md). Изменения предыдущих этапов сохранены в той
же рабочей копии. Между этапами installer не дублируется: сборка 7–8 выполняется
после последовательного завершения необязательных возможностей.

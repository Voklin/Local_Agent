# 2. Технологии и их роль

Точные диапазоны и зафиксированные npm-версии вынесены в [генерируемую таблицу зависимостей](reference/dependencies.md). Она строится из package.json и lock-файла, а не из предположений о текущей версии библиотеки.

## Python: язык ядра

Python-код описывает правила работы агента: какое сообщение отправить модели, как собрать вызов инструмента, как проверить путь и как сохранить чат. Файл `.py` — модуль. `import` связывает модули; относительный импорт `.tools` означает соседний модуль Python-пакета `agent`.

Функция группирует действие и параметры. Например, `resolve_allowed_path(root, requested, must_exist=False)` преобразует пользовательский путь в проверенный `Path`. Класс хранит связанные данные и поведение: экземпляр `AgentEngine` относится к одному запуску задачи, `TaskService` — к обслуживающему процессу и выбранному чату.

`__init__` инициализирует экземпляр. `self` — этот экземпляр. Метод `_checkpoint` начинается с подчёркивания, что обозначает внутреннее использование по соглашению, а не запрещает вызов технически. Аннотация `Path | None` описывает ожидаемый тип; обычный Python сам не выполняет полную runtime-проверку таких аннотаций.

`dataclass` уменьшает шаблонный код для записей, например `PlanStage` и `ModelEndpoint`. Словари представляют JSON-подобные записи. Исключения отделяют ошибочный путь от успешного результата; `execute_tool` переводит ряд исключений в словарь `{ok: false, error: ...}`.

## Поток, процесс и корутина

Процесс имеет отдельную память и собственный интерпретатор. Electron запускает Python как дочерний процесс. Потоки внутри Python делят память: сервисный поток задачи может видеть флаг `Event`, выставленный обработчиком команды остановки. Это требует согласования доступа к общему состоянию.

Корутина — приостанавливаемое вычисление. `await` отдаёт управление event loop, пока сетевой ответ не готов. В `model_client.py` отдельный поток исполняет event loop; синхронный агент передаёт туда запрос через `run_coroutine_threadsafe`. Очередь возвращает чанки обратно. Такой переход позволяет сохранить существующий синхронный цикл инструментов и отменять сетевой запрос.

Асинхронность здесь решает ожидание ввода-вывода, а не ускоряет вычисление токенов внутри модели. GPU-вычисления выполняет сервер модели. Семантика задач, отмены и межпоточного планирования описана в [документации asyncio](https://docs.python.org/3.12/library/asyncio-task.html).

## JavaScript и TypeScript

JavaScript выполняется в Node.js и в Chromium-странице Electron. TypeScript добавляет статические описания типов, после чего сборщик создаёт исполняемый JavaScript. Например, `FileItem` ограничивает `kind` значениями `'file' | 'directory'`, а `Promise<any>` означает асинхронный ответ с ещё слабо описанным содержимым.

Компилятор помогает находить несогласованные вызовы до запуска. Но `any` ослабляет проверку, а TypeScript-типы не заменяют проверку входных JSON-данных в Python. Изучайте эти различия через [TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html).

## React и JSX

`App.tsx` — React-компонент: функция, возвращающая дерево интерфейса. JSX похож на HTML, но позволяет вставлять выражения JavaScript в `{...}`. Условие `approval && <...>` показывает диалог только при наличии предложения записи.

`useState` хранит данные, влияющие на отрисовку: чат, выбранную модель, список файлов. `useRef` хранит изменяемые значения без обязательного нового рендера: текущие `chat_id` и `run_id`. `useEffect` подключает слушатель событий и возвращает функцию отключения. Данные текут от состояния к представлению; прямое изменение DOM обычно не является способом обновлять React-интерфейс. Исключение в нашем smoke-тесте — имитация действий пользователя для проверки приложения. Базовый учебный источник — [React Quick Start](https://react.dev/learn).

## Electron

Electron соединяет Chromium для UI и Node.js для настольных возможностей. Main-процесс создаёт окно и запускает Python. Renderer рисует интерфейс. Preload предоставляет небольшой объект `window.lca` через `contextBridge`; renderer не получает общий доступ к Node.js.

`contextIsolation`, `sandbox` и `nodeIntegration: false` относятся к изоляции renderer. Проверка папки проекта в Python — отдельный механизм. Важное следствие архитектуры: обычная веб-страница, открытая через Vite, не имеет Electron preload и не является полноценным запуском нашего приложения. Подробнее — [официальная модель процессов Electron](https://www.electronjs.org/docs/latest/tutorial/process-model).

## Vite, npm и CSS

Vite обслуживает UI при разработке и собирает ресурсы в `dist/`. В нашем коде его API также собирает `main.ts` и `preload.ts` в CommonJS `.cjs`. `external: ['electron', ...]` оставляет системные импорты внешними для runtime.

npm устанавливает зависимости. Корневой `package.json` объявляет workspace `apps/desktop`, поэтому команды из корня делегируются туда. `package-lock.json` фиксирует конкретное дерево зависимостей; `npm ci` воспроизводит его. Руководства: [Vite](https://vite.dev/guide/) и [npm workspaces](https://docs.npmjs.com/cli/v11/using-npm/workspaces/).

CSS в `style.css` управляет цветами, размерами панелей, прокруткой и диалогом. CSS-переменные `--bg`, `--panel`, `--blue` образуют небольшой набор визуальных настроек. Иконки берутся из `lucide-react`; это визуальные компоненты, а не команды агента.

## HTTP, JSON, SSE и SDK

HTTP соединяет ядро с сервером модели. JSON передаёт сообщения и аргументы инструментов. SSE возвращает отдельные события в одном HTTP-ответе: текст может появляться раньше окончания генерации. Локальный JSON-lines мост — другой протокол: каждая строка stdout содержит один JSON-объект.

Проект использует пакет `openai` как клиент совместимого API и `AsyncOpenAI` для отменяемых запросов. Фактический ресурс — Chat Completions; внешний SDK сам не добавляет наш планировщик, sandbox или подтверждение файлов. Эти механизмы написаны в LocalAgent. Возможность использовать произвольный `base_url` не гарантирует, что каждый сервер поддерживает все поля, streaming и tool calling одинаково. См. [OpenAI Python SDK](https://developers.openai.com/api/reference/python) и [официальное описание streaming](https://developers.openai.com/api/docs/guides/streaming-responses).

## GGUF и llama.cpp

GGUF — формат файлов моделей, с которыми работает сохранённый `ModelManager`. `LocalRuntime` умеет запустить отдельный `llama-server`, но этот путь не подключён к текущим кнопкам Electron. Файл модели не является Python-библиотекой и не попадает автоматически в npm-сборку. Детали сервера изучайте в [документации llama.cpp server](https://github.com/ggml-org/llama.cpp/tree/master/tools/server).

## Git и GitHub Actions

Git хранит снимки исходников и историю изменений. Ветка указывает на коммит; pull request предлагает объединить ветку с другой. GitHub Actions исполняет команды на отдельной Windows-машине, а не управляет вашим локальным экземпляром приложения. Успешный CI подтверждает выполненные проверки, но не качество каждого ответа любой модели. Учебные источники: [Pro Git](https://git-scm.com/book/en/v2) и [GitHub Actions](https://docs.github.com/en/actions).

## Как закрыть подробности работы модели

В Chat и IDE панель «Ход задачи» теперь можно скрыть четырьмя способами:

1. Крестиком в заголовке «Работа модели».
2. Клавишей Escape.
3. Щелчком за пределами панели.
4. Повторным нажатием «Ход задачи».

Скрытие не отменяет модельный запрос, инструменты или задачу. Отдельная кнопка
«Остановить» сохраняет своё прежнее назначение. При закрытии крестиком/Escape
фокус возвращается переключателю панели. Нажатия внутри и прокрутка панель
не закрывают. Заголовок с крестиком остаётся доступным при прокрутке.
Если открыт модальный диалог, Escape обрабатывает его, не закрывая заодно
подробности. Кнопки согласия на файловые изменения не подменяются скрытием панели.

Основной код: [App.tsx](../apps/desktop/src/App.tsx), методы `closeProgress`
и `dismissProgress`; оформление — [neutral.css](../apps/desktop/src/styles/neutral.css).
Панель имеет именованный region, переключатель — `aria-controls`/`aria-expanded`.

## Новые инструменты агента

Они доступны в IDE через включённую группу файлов проекта. Модель выбирает
операцию, пользователь видит её результат в ходе задачи. Изменения требуют
отдельного preview/согласия, как и прежде. Список tools и их выключение находятся
в «Настройки → Расширения → Инструменты».

| Инструмент | Использование и ограничения |
| --- | --- |
| `glob_files` | Поиск имён `*.py`, `src/**/*.ts`. Маска без `/` применяется к имени файла; `*` внутри сегмента не переходит в другую папку, `**` допускает ноль и больше папок. До 2000 результатов. |
| `search_text` | Тот же literal search, что в панели поиска IDE: query, path, pattern, case_sensitive, limit, max_depth. До 200 совпадений. |
| `read_range` | `path`, start_line/end_line с нумерацией от 1, максимум 400 строк и 12 000 символов выдачи; по умолчанию 200 строк. Возвращает SHA256 всей ревизии и next_line. |
| `patch_file` | Заменяет один уникальный old_text на new_text. Ноль и несколько совпадений дают ошибку, файл не меняется. Опциональный expected_sha256 связывает предложение с предыдущим чтением. |
| `create_directory` | Создаёт недостающую цепочку каталогов внутри проекта, максимум 30 уровней. Существующий каталог возвращает unchanged, без лишнего согласия и обновления памяти. |
| `rename_file` | Перемещает один обычный файл в существующую папку проекта. Назначение должно отсутствовать; замены существующего файла нет. |
| `delete_file` | Удаляет один UTF-8 файл после diff. Каталоги рекурсивно не удаляются; корзины и автоматического восстановления пока нет. |
| `get_project_instructions` | Подключает применимые AGENTS.md от корня до выбранного пути к следующему модельному запросу. Не расширяет права. |

Прежние `list_files`, `read_file`, `write_file` сохранены. Для новой вложенной
структуры используйте create_directory, затем write_file. Для небольшого изменения
предпочтителен patch_file: модель передаёт фрагмент, а не весь исходный файл.
Все schemas новых tools проверяются до исполнения.

В диалогах явно различаются «Создание каталогов», «Точечная правка»,
«Перемещение файла», «Удаление файла». Кнопки подтверждения называют действие.
Удаление дополнительно сообщает, что файл исчезнет с диска и восстановления
в приложении ещё нет. После применения обновляется проводник; существующий
редактор продолжает защищать несохранённые черновики своим механизмом ревизий.

## Один поиск для UI и модели

Алгоритм перенесён в [workspace_search.py](../agent/workspace_search.py).
[core/python/project_search.py](../core/python/project_search.py) теперь содержит
асинхронный worker, использующий эту же функцию. `search_text` и `glob_files`
вызывают общий алгоритм через [tools.py](../agent/tools.py).

По умолчанию: deadline 3 секунды, до 15 000 файлов, 30 000 элементов обхода,
10 МБ чтения и 1 МБ на отдельный файл. Игнорируются обычные каталоги зависимостей,
Git, окружений и сборок. Symlink/junction не обходятся; внешние пути не расширяют
выбранный корень. Маски не являются произвольным регулярным выражением.

Проверка отмены выполняется в процессе обхода и каждые 64 строки поиска.
Stop задачи передаёт Event в инструмент; UI-поиск имеет свою кнопку отмены.
Результат различает cancellation и достижение time/files/bytes/depth/results
лимита, содержит scanned_files/skipped_files. Модель может сузить путь/маску
или продолжить исследование, а не принимать обрезанную выдачу за полный проект.

## Чтение диапазона и точечная правка

[workspace_read.py](../agent/workspace_read.py) читает не более 8 МБ небольшими
блоками, проверяя отмену и время. Для SHA256 и числа строк backend сканирует
файл целиком, но модели выдаёт только выбранные строки. Это не случайный доступ
по индексу большого файла. Данные должны быть UTF-8 без NUL.

CRLF и остальные байты не нормализуются при выдаче. Если одна строка превышает
12 000 символов, возвращается LINE_TOO_LONG, а не незаметно усечённая строка.
При изменении источника во время чтения возвращается FILE_CHANGED.

`patch_file` в [workspace_edits.py](../agent/workspace_edits.py) проверяет уникальность
фрагмента на текущей ревизии. Для файла целиком с CRLF входной фрагмент LF
согласуется с CRLF, неизменённые байты сохраняются. Смешанные newline не
переписываются глобально. Итоговая запись использует прежний snapshot-checked
атомарный `write_file`. Лимит изменения — 1 МБ исходника/нового содержимого;
чтение большего файла ещё не означает возможность переписать его этим инструментом.

## Preview, согласие и журнал

`preview_mutation` не меняет диск. Snapshot содержит вид операции, hash аргументов,
путь, SHA256/identity исходника, identity родителя и сведения назначения.
Для каталогов фиксируются существующий предок и конкретная недостающая цепочка.

`ToolExecutor._mutate` выполняет следующий порядок:

1. Проверка актуальности локальных инструкций.
2. Preview и состояние awaiting_approval в долговечном журнале.
3. Показ намерения пользователю и получение одноразового решения.
4. Повторная проверка правил, затем durable started перед побочным эффектом.
5. `apply_mutation`: новый preview/snapshot должен совпасть с подтверждённым.
6. Сохранение квитанции, обновление task/UI и только затем следующий запрос модели.

Ручное изменение файла, появление назначения или замена родителя отменяют прежнее
предложение. Требуется новый preview; старое согласие не даёт права затереть правку.
Новые операции отказываются менять корень, служебный `.git` и пути через
symlink/junction. Переименование/удаление папок и cross-volume перенос не добавлены.

На Windows rename использует отказоустойчивый к существующему назначению
`os.rename`. На POSIX для запрета замены используется link/unlink; это не единая
транзакция. Цепочка mkdir также не является атомарной транзакцией. Если ошибка
или отмена возникла после части эффектов, возвращается OUTCOME_UNKNOWN с доступными
сведениями. Созданные папки автоматически не удаляются: в них уже могли появиться
пользовательские файлы. Проверьте фактическую структуру через карточку восстановления.
Обычные инструменты приложения не заменяют изоляцию файловой системы средствами ОС.

`workspace_changes` содержит последние 100 структурированных успешных событий.
`record_workspace_change` восстанавливает их из receipts без повторного patch,
rename или delete. В UI показаны операции и пути; сырой код в task не дублируется.
Неизвестный исход продолжает блокировать автоматический повтор по правилам этапа 2.

Исправлена и отмена предложения с промежуточным текстом assistant: фраза
«Сейчас создам файл» больше не позволяет отметить отменённую задачу completed.
Отмена остаётся paused, скрытие подробностей оставляет активный запуск работающим.

## Инструкции проекта

[ProjectInstructions](../agent/project_instructions.py) автоматически читает
корневой AGENTS.md. При read_file/read_range/get_project_instructions либо
предложении изменения подключаются правила папок от корня к выбранному пути.
В случае перемещения проверяются исходный и новый пути.

Каждая запись имеет path, scope, SHA256 и generation. Полный текст правил
передаётся в system projection и учитывается полным бюджетом этапа 3.
Более глубокие правила уточняют родительские только в своей области;
прямые указания пользователя имеют приоритет. Никакой AGENTS.md не может
разрешить внешнюю папку, shell/MCP без согласия или ранее выключенный инструмент.

Если правила впервые обнаружены или изменились, запись возвращает
PROJECT_INSTRUCTIONS_REQUIRED до показа согласия/исполнения. Только следующий
модельный запрос с новой версией правил разрешает повторное предложение.
Несколько calls одной пачки не обходят эту границу. Эта запись считается
подключением правил, а не ошибкой инструмента или отсутствием прогресса.
Смена правил после согласия также требует нового обращения к модели.

Лимиты: 8 КБ на файл, 16 КБ на прочитанный набор, 64 источника.
Превышение даёт явную ошибку; правила не обрезаются. Task/UI хранят только
источники, области и hashes. Не выполняется рекурсивное предварительное чтение
всех AGENTS.md проекта. За пределы выбранного корня поиск инструкций не выходит.

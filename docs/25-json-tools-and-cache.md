# 25. Области чатов, JSON tool calling и квантование KV-кеша

## Разделение истории

История хранит поле `mode`: `chat`, `ide`, `voice`. `project_root` продолжает
отделять IDE-проекты. Список, загрузка, rename и запуск проверяют **оба** значения.
Мия не попадает в Chat даже при одинаковом пустом `project_root`.

`agent/chat_store.py` добавляет mode в канонический файл и производный индекс.
`TaskService.chats/select_chat/rename/start` проверяют область на стороне Core;
фильтрация только в React не считалась бы изоляцией. `App.refreshChats` больше
не подменяет voice на chat. В голосовом режиме доступна собственная история.

У старых файлов отсутствовал mode, а сообщения не содержали надёжного маркера
Мии. Они сохраняются в прежней области Chat; приложение не угадывает по тексту.
Кнопка «М» в истории переносит выбранный разговор к Мие, «C» переносит обратно.
`TaskService.move_chat` меняет только mode существующей записи, сохраняя сообщения,
ID, заголовок и checkpoint. Перенос обратим.

## Два протокола инструментов

В настройках основной модели и отдельно Мии выбирается `Native tools API` либо
`JSON в тексте`. JSON предназначен для моделей вроде Qwen 2.5 Coder, у которых
сервер/шаблон не поддерживает нативное поле tools. Приложение не обещает, что
любая маленькая модель будет корректно следовать инструкциям: parser выполняет
только валидный протокол и разрешённые инструменты.

Пример единственного ответа модели для вызова:

```json
{"tool_calls":[{"name":"read_file","arguments":{"path":"README.md"}}]}
```

Также принимается целый объект `{"tool":"read_file","arguments":{"path":"README.md"}}`.
Обычный конечный ответ остаётся текстом. Пример JSON, окружённый объяснением,
не исполняется. Принимается envelope в самом начале ответа или целый fenced json-блок.
Комментарий после начального JSON игнорируется: Qwen 2.5 Coder может добавлять
обещание после корректного объекта. Поиск JSON внутри произвольного текста не выполняется. Доступно от 1 до 8 вызовов за ответ; имена проверяются
по definitions текущего режима; arguments обязаны быть объектом.

Путь запроса:

1. `ModelClient.create` видит выбранный JSON protocol и вызов с tools.
2. `prepare_json_request` удаляет tools/tool_choice из HTTP JSON, добавляет схему
   и формат в системную инструкцию. Каноническую tool history переводит в обычные
   assistant/user сообщения; нет API role=tool, который сервер может не понимать.
3. `JsonToolStream` читает отменяемый `ModelStream`, буферизует не больше 1 МБ,
   проверяет весь ответ и создаёт обычные `delta.tool_calls` с уникальными ID.
4. `AgentEngine` использует прежний dispatcher, журнал и checkpoint. Отдельного
   обходного исполнителя команд или shell нет.
5. `write_file` по-прежнему сначала делает snapshot/diff и ждёт apply/reject.
   Проверка revision защищает от внешнего изменения между preview и apply.

Во время JSON-генерации служебный JSON не выводится пользователю кусками; обычный
ответ появляется после полной проверки. Native protocol сохраняет прежний streaming.
JSON не делает модель компетентнее и не отменяет ограничения выбранной папки.

Файлы: [`json_tools.py`](../agent/json_tools.py),
[`model_client.py`](../agent/model_client.py), [`engine.py`](../agent/engine.py).
Контракт end-to-end: [`test_json_protocol.py`](../tests/migration/test_json_protocol.py)
поднимает настоящий HTTP-сервер, который отвергает native tools. JSON-модель
читает fixture, предлагает запись, ждёт diff approval и только затем создаёт файл.

## KV-кеш

Настройки «KV-кеш K» и «KV-кеш V» относятся к запущенному самим LocalAgent
llama-server, а не к HTTP-клиенту. Доступны f16, q8_0, q4_0. Значения независимо
проверяются в `RuntimeService.start` до запуска процесса; произвольные CLI-аргументы
из renderer не принимаются.

Core формирует `--cache-type-k`, `--cache-type-v`. Для квантованного V включает
`--flash-attn on`, иначе использует auto. Поддержка комбинации зависит от
архитектуры модели и сборки CPU/GPU; ошибка сервера показывается вместе с последним
выводом. Это квантование рабочего attention cache, а не повторное квантование весов
GGUF и не «сжатие истории чата».

При старте cache/context/GPU/threads сохраняются в runtime-preferences.json
в app data и восстанавливаются в следующем окне/сеансе. Пути моделей в этом
файле не сохраняются. Настройки меняются до старта. Поле «Потоки CPU» задаёт от 1 до 128 потоков.
LocalAgent запускает один parallel slot: агент выполняет один активный запрос.
Готовность проверяется через /health, отдельно от списка моделей. Для уже запущенного внешнего LM Studio нужно менять
KV-cache в самом LM Studio и перезагружать модель: клиент LocalAgent не может
поменять тип памяти чужого процесса через Chat Completions.

Источник параметров: [официальный llama.cpp server b11829](https://github.com/ggml-org/llama.cpp/blob/b11829/tools/server/README.md).

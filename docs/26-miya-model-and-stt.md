# 26. Мия: характер, своя модель, голос и распознавание

## Профиль и модель

В режиме Ассистент откройте «Характер, отдельная модель и распознавание».
Укажите endpoint и ID отдельной модели Мии. «Загрузить модели Мии» читает именно
этот endpoint. Можно использовать другой ID на одном сервере с основной моделью
либо отдельный сервер. LocalAgent не выбирает и не загружает веса автоматически:
одновременная загрузка нескольких моделей зависит от сервера и доступной памяти.

Характер — пользовательская инструкция до 6000 символов. Профиль сохраняет voice,
rate, volume, auto_speak, auto_delegate, собственные base_url/model/tool_protocol,
generation settings и настройки STT. `companion.json` находится в app data.
Ключи модели и STT остаются в памяти Core и не записываются в профиль/чат.

[`companion_preferences.py`](../agent/companion_preferences.py) содержит defaults,
валидацию и атомарную запись. [`CompanionSettings.tsx`](../apps/desktop/src/CompanionSettings.tsx)
показывает независимую форму. `TaskService.start` для voice выбирает именно этот
профиль; изменение основной модели не переписывает ID Мии. Пока ID Мии пуст,
интерфейс предлагает выбрать её модель.

## Передача основной модели

Мия получает `delegate_task(target, prompt)`, где target — Chat либо IDE.
Файловых write/read/search инструментов проекта у неё нет. При включённых PC tools
доступны только отдельные ограниченные инструменты из [главы 27](27-desktop-and-telegram.md).
Даже если модель вернёт необъявленный `write_file`, Core отклонит его до preview.

`request_delegation` сохраняет одну pending передачу с UUID, исходным voice chat
и **первоначальным человеческим запросом**. Ответ tool означает «передача поставлена
в очередь», а не «задача выполнена». После завершения ответа Мии интерфейс показывает
задание основной модели. При включённом auto_delegate запускает его автоматически;
при выключенном доступна кнопка запуска. Для IDE нужна выбранная папка проекта.

`prepare_handoff` создаёт отдельный чат основной модели, не смешивая его tool history
с Мией. Отдельные PC folder grants берутся из исходного пользовательского запроса,
а не из переформулированного задания модели. Основной executor сохраняет обычный diff
approval. После завершения текстовый итог добавляется в исходную voice историю;
кнопка «Результат готов · вернуться к Мие» открывает её. Источник остаётся отдельным
от общего Chat и истории IDE.

## Голос

Системный Windows TTS сохраняет поддержку установленных голосов System.Speech.
Выберите голос, темп и громкость, затем «Сохранить голос». Auto-speak относится
только к новым завершённым ответам. Stop озвучки и Stop задачи остаются разными
действиями. Новые произвольные голоса или voice cloning этой настройкой не создаются.

## STT: микрофон → WAV → текст

1. Настройте запущенный STT-сервер. Для локального whisper.cpp полный URL обычно
   `http://127.0.0.1:8080/inference`. Для OpenAI-совместимого сервера используйте
   полный URL его `/v1/audio/transcriptions`, model ID и при необходимости ключ.
2. Нажмите «Микрофон · запись». Запись начинается только по нажатию пользователя.
   Electron разрешает только audio для своего webContents; video не разрешается.
3. Нажмите «Завершить запись» либо дождитесь лимита 60 секунд.
4. Проверьте распознанный текст в поле сообщения; отправка выполняется отдельно.

Класс [`MicrophoneRecorder`](../apps/desktop/src/microphone.ts) получает MediaStream,
создаёт AudioContext 16 kHz и копирует mono float samples. ScriptProcessor подключён
через gain=0: захват не воспроизводится в динамиках. `finish()` строит RIFF/WAVE
PCM16 header, преобразует samples в signed int16, кодирует base64 и освобождает tracks.
`dispose()` вызывается также при ошибке, отмене и закрытии голосовой панели. Аудио
не записывается на диск. Пустая запись отклоняется.

[`TranscriptionService`](../core/python/transcription_service.py) ограничивает base64
2.6 МБ и проверяет WAV: mono, 16-bit, 16000 Hz, не более 960000 frames. Worker
посылает multipart file/model/language/response_format=json через HTTPX. Core bridge
остаётся отзывчивым. Cancel закрывает клиент; shutdown ждёт worker ограниченное время.
Ошибки не выводят ключи или сырые URL с credential.

STT endpoint — отдельный работающий сервис и загруженная speech-модель. Включённый
llama.cpp CPU runtime для текстовых GGUF сам по себе не является Whisper.
Без настроенного STT-сервера запись возможна, но распознавание вернёт ошибку
подключения. Голосовые модели в установщик не добавляются автоматически.

Официальный протокол локального сервера:
[whisper.cpp server](https://github.com/ggml-org/whisper.cpp/blob/master/examples/server/README.md).

В 6.2 доступны Qwen3-TTS VoiceDesign и фраза активации во всех режимах: [глава 29](29-neural-voice-and-wake.md).

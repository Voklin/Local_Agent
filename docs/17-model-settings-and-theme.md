# 17. Настройка модели и общая палитра

## Как пользоваться

Откройте шестерёнку в любом из трёх пространств. Настройки теперь находятся в отдельном широком окне, а не в узкой колонке файлов. Подключение, генерация и лимиты общие для Chat и IDE. Во время задачи значения доступны для просмотра, редактирование заблокировано. Внутренняя прокрутка оставляет кнопки сохранения и результат операции видимыми.

1. Запустите сервер отдельно. Быстрые кнопки задают адрес LM Studio `http://127.0.0.1:1234/v1` или Ollama `http://127.0.0.1:11434/v1`; произвольный OpenAI-совместимый endpoint можно ввести вручную.
2. При необходимости введите API-ключ. Глаз показывает/скрывает введённое значение; это не сохраняет его на диск.
3. «Проверить сервер и загрузить модели» выполняет GET `/models` по адресу из окна. Выберите модель из списка либо введите ID. Наличие ID в ответе сервера не доказывает, что модель уже загружена и отвечает.
4. «Проверить ответ модели» отправляет отдельный короткий Chat Completions запрос, без файлов, инструментов и истории. Результат и время видны внизу. Сервер может автоматически загрузить выбранную модель. Операцию можно отменить.
5. Отредактируйте генерацию и лимиты. «Сбросить параметры» возвращает только числовые defaults в черновике; адрес, ID и ключ сохраняются в полях окна.
6. Нажмите «Сохранить настройки». Только успешное сохранение обновляет применённую конфигурацию. Закрытие без сохранения отбрасывает черновик; существующие чаты не удаляются.

Окно удерживает Tab-фокус внутри доступных контролов, Escape закрывает его вне сетевой операции, после закрытия фокус возвращается на прежний элемент. Ошибка имеет `role=alert`, обычный результат — `role=status`. Во время discovery/probe поля блокируются, чтобы ответ не относился к уже изменённому endpoint.

## Параметры и их реальный эффект

| Поле | Default | Диапазон | Где применяется |
| --- | --- | --- | --- |
| Temperature | 0.2 | 0–2 | Основной модельный цикл и диагностический запрос |
| Top P | 1 | 0.01–1 | Основной модельный цикл и диагностический запрос |
| Максимум токенов ответа | 8192 | целое 64–32768 | max_tokens основного цикла и probe; это общий бюджет генерации, у reasoning-модели он может включать рассуждения |
| Бюджет контекста, символов | 80000 | целое 12000–500000 | Сокращение рабочего контекста сообщений; канонический архив не обрезается |
| Ожидание HTTP, секунд | 180 | целое 5–600 | Сетевой timeout ModelClient, в том числе вспомогательных вызовов проверки/памяти |
| Максимум циклов агента | 200 | целое 1–500 | Основной цикл, включая повторы пустого ответа |
| Время задачи, минут | 180 | целое 1–1440 | Общая проверка elapsed между циклами; не мгновенное прерывание активного HTTP |

Контекст в символах не равен контекстному окну модели в токенах и не управляет выделением VRAM. Размер окна, GPU-слои, квантование, загрузка GGUF и chat template остаются настройками внешнего сервера. Допустимое значение в приложении не гарантирует, что конкретная модель/сервер принимает его: например, max_tokens может превышать доступный размер окна. Сервер тогда вернёт явную ошибку.

Вспомогательная модельная проверка завершённости сохраняет собственные фиксированные sampling/token лимиты; обновление памяти тоже использует свой ограниченный вызов. Поля temperature/top_p/max_tokens прежде всего управляют основным ответом и probe, а не переопределяют внутренние служебные задачи.

## Черновик и сохранённая конфигурация

`ModelSettings` копирует начальную конфигурацию в локальный React state `draft`. Вложенный settings также копируется, чтобы нажатия не меняли уже применённые значения родителя. Числовые поля допускают промежуточный пустой ввод, но `validate` не позволяет отправить пустоту/NaN или дробь вместо целого. Backend независимо повторяет все проверки: ограничения HTML не считаются защитой данных.

`model-preferences.json` содержит `base_url`, `model`, `settings`. `validate_settings` обходит только whitelist семи полей, отвергает bool, нечисловые значения, NaN/Infinity, дробные integer-поля и выход за границы. Неизвестные поля не сохраняются. Сначала валидируется весь объект, затем временный файл атомарно заменяет прежний; невалидный запрос не портит последний рабочий JSON.

Старый файл с двумя полями URL/ID читается без миграционной команды: недостающие settings получают defaults, адрес и модель сохраняются. API-ключ есть только в памяти процесса и окне; ответ `get_model_settings` его не возвращает. После перезапуска ключ нужно ввести заново. В этой версии нет системного менеджера секретов или постоянных профилей нескольких серверов.

После Save `App` обновляет применённые значения и использует их при следующем старте. `TaskService` передаёт settings в `AgentEngine`; engine добавляет sampling в настоящий HTTP payload и задаёт timeout клиента. Новые поля не являются декоративными настройками интерфейса.

## Discovery, probe и IPC

| API renderer | IPC | RPC | Семантика |
| --- | --- | --- | --- |
| listModels(config?) | model:list | list_models | Необязательный draft; без аргумента используется сохранённая конфигурация |
| testModel(config) | model:test | test_model | Фоновая проверка текстового ответа черновой модели |
| cancelModelSetup() | model:cancel-setup | cancel_model_setup | Отмена discovery/probe, не прерывающая задачу агента |
| configureModel(config) | model:configure | configure_model | Валидация и применение/сохранение |
| getModelSettings() | model:settings | get_model_settings | URL, ID и settings без ключа |

`main.modelConfig` перечисляет допустимые верхние поля. Main не принимает произвольный prompt для probe и не открывает общий механизм вызова backend. Bridge запускает discovery/probe в отдельных потоках; health, cancel и другие команды не ждут ответа модели. Каждый worker получает отдельную копию конфигурации и отвечает по исходному ID. Повтор того же вида диагностики во время её исполнения отклоняется.

Discovery сохраняет лимит 5 секунд и 1 МБ. Probe имеет общий deadline 30 секунд, ограничение 100 000 байт ответа и сетевой timeout не больше 30 секунд либо меньшего выбранного пользователем. IPC ожидает probe до 35 секунд; остальные RPC — до 10 секунд. Тайм-ауты разных слоёв намеренно различаются: backend должен успеть вернуть диагностическую ошибку раньше main.

Probe передаёт фиксированный краткий system prompt и арифметический вопрос, выбранные temperature/top_p/max_tokens, `stream=False`. Он не исполняет tools, не добавляет диалог в историю и не сохраняет черновик. Успех означает корректную структуру Chat Completions и непустой текст; это не полная оценка точности модели или поддержки инструментов. Внутренние рассуждения не выдаются за пользовательский ответ. При reasoning-only результате показана отдельная ошибка с подсказкой про бюджет. Проверка с искусственно малым бюджетом может закончиться без content даже у рабочей модели, поэтому probe использует выбранный бюджет, а не скрытый меньший лимит.

`_probe` соревнуется запросом и Event отмены через asyncio.wait. В finally обе задачи отменяются и ожидаются; async context HTTPX закрывает соединение. `cancel_model_setup` не вызывает engine.requestInterruption. EOF/shutdown отменяет обе диагностики и дожидается их потоков с ограничением времени.

`draft` — несохранённое состояние формы, `snapshot` — копия конфигурации уже начатой операции. Whitelist ограничивает набор сохраняемых полей, но не определяет поддерживаемые сервером модели. Finite check отвергает специальные числовые значения, которые могут пройти обычную проверку типа float. Timeout сетевой операции, общий deadline теста и elapsed задачи — три разных ограничения.

## Единая схема IDE

В общий :root добавлены токены surface, surface-raised, surface-soft, surface-inset, accent и accent-border. IDE теперь использует те же графитовые поверхности и сиреневые акценты: вкладки, проводник, приветствие, кнопки, output, панель плана, инструментальные карточки, focus и diff-dialog. Зелёный/жёлтый/красный остаются семантическими статусами успеха, ожидания и ошибки. CSS не изменяет права записи или поведение инструментов.

## Самостоятельные проверки

Unit-тесты проверяют старый JSON, roundtrip генерации и отказ невалидным значениям без перезаписи. HTTP-тесты подтверждают фактический payload движка, отсутствие сохранения draft/ключа, текстовый результат, ошибки структуры/401/размера, deadline и отмену. Новый subprocess-сценарий оставляет probe зависшим, выполняет health/cancel и проверяет, что черновая модель не сохранена. Он выполняется также с frozen Core и урезанным PATH.

Electron smoke проходит настоящее окно: сервер, ID модели, probe, изменение temperature/max_tokens, Save, значения после reload, пустой ключ после перезапуска renderer, затем прежние Apply/conflict/streaming/Stop и три режима. Для IDE проверяется вычисленный фон общей палитры. Packaged smoke дополнительно проверяет сохранение числовых настроек между двумя запусками exe и новый testModel IPC. Снимки settings/IDE сохраняются только как локальные тестовые артефакты.

В текущей ручной проверке загруженная qwen3.5-4b в LM Studio вернула текст «42» за 1750 мс через новый probe. Это подтверждает один реальный диагностический сценарий; полный набор моделей/серверов отдельно не сертифицирован.

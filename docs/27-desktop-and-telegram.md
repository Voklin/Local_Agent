# 27. Инструменты ПК и Telegram

## Включение инструментов ПК

В настройках модели откройте «Инструменты ПК и Telegram» и включите PC tools.
Состояние enabled сохраняется отдельно; новые папки не попадают в постоянный
allowlist. Переключение применяется вне активной задачи.

Доступные инструменты:

| Инструмент | Действие и граница |
| --- | --- |
| desktop_screenshot | Снимок основного экрана, только при явном запросе скриншота |
| browser_search | DuckDuckGo с резервным Bing RSS, до 8 ссылок/заголовков/фрагментов; открытие Bing в обычном браузере |
| list_applications | Названия и ID разрешённых приложений без путей к EXE |
| open_application | Запуск ID из списка, без shell, команд и аргументов |
| list_allowed_folder | Read-only список папки из исходного запроса пользователя |
| read_allowed_file | Ограниченное чтение UTF-8 внутри явно указанной папки |

Пример: `Посмотри папку "C:\Projects\Demo" и опиши файлы.` Для путей с пробелами
нужны двойные кавычки. `prompt_folders()` разрешает существующие абсолютные папки
и проверяет результат resolve; модель, tool result и веб-страница не могут добавить
grants. Симлинк наружу не становится разрешённым путём. Делегирование сохраняет
исходный человеческий запрос для этой проверки.

## Приложения и поиск Мии (6.3)

Скажите «Открой калькулятор» или «Найди в браузере информацию о…».
Мия получает инструменты ПК напрямую, включая JSON tool calling для моделей
без нативного протокола. Для открытия она сначала запрашивает `list_applications`,
затем передаёт `app_id` в `open_application`. Эти действия не требуют делегирования
основной модели. Сообщение об открытии означает запуск приложения, а не управление
его окнами, документами или кнопками.

В «Инструменты ПК и Telegram» → «Разрешённые приложения» показаны Браузер,
установленные Блокнот, Калькулятор, Paint и Проводник. «Добавить приложение…»
открывает системный выбор EXE. Можно добавить до 30 локальных EXE и убрать
добавленные разрешения. Модель не имеет инструмента добавления или изменения списка.
Каталог хранится в `desktop-apps.json` внутри Electron userData; Core не получает
исполняемые пути. Host независимо сопоставляет ID с каталогом и вызывает
`spawn(file, [], {shell:false})`. Аргументы, скрипты и пути от модели отклоняются.
Отсутствующий или удалённый EXE не запускается, существующий файл выбирается вручную.

Поиск читает только выдачу: до 1 МБ ответа, до 8 результатов и до 600 символов
заголовка/фрагмента. При отказе DuckDuckGo используется Bing RSS без ключа API;
XML DTD и ссылки с протоколами, отличными от HTTP/HTTPS, отвергаются. Браузер
открывается по фиксированному HTTPS URL Bing с закодированным запросом.
Если результаты получить не удалось, ответ инструмента явно сообщает, что открыт
только браузер и содержимое не прочитано. Полные страницы этим инструментом не
читаются. Поисковые результаты — внешние данные, их релевантность зависит от сервиса.

Каталог и ограничения: [`desktopApps.ts`](../apps/desktop/electron/desktopApps.ts).
Проверки: [`desktop-apps.cjs`](../tests/electron/desktop-apps.cjs),
[`test_expansion.py`](../tests/test_expansion.py) и Electron smoke с настоящим IPC.

Обычные IDE-инструменты продолжают работать внутри папки, выбранной пользователем
для проекта. PC tools дают дополнительное read-only чтение только указанных в
сообщении папок; произвольный shell, запись вне проекта и удаление не предоставлены.

`DesktopService.request` создаёт одноразовый host request UUID. Electron выполняет
только screenshot, search, list_applications или open_application. Ответ должен совпадать с pending UUID. Скриншот
1280×720 показывается в приложении и не записывается на диск. Текущий текстовый
протокол возвращает capture ID и честно сообщает модели, что картинка показана
пользователю: автоматический VLM-анализ/управление мышью этим действием не реализованы.

Поиск читает фиксированные HTTPS endpoints DuckDuckGo и Bing RSS. Парсеры не исполняют
страницы/JS; payload ограничен 1 МБ, есть тайм-аут и проверка отмены. Challenge,
пустая и явно нерелевантная выдача не превращаются в выдуманный результат.

## Telegram: настройка

Пользователь отдельно разрешил передавать через своего бота своему user ID ответы
агента, путь проекта и diff для удалённого подтверждения.

1. Введите BotFather token в password-поле приложения и собственный числовой
   Telegram user ID. Никакие токены не нужно помещать в чаты проекта или Git.
2. При желании включите «Сохранить токен защищённо на этом ПК». Electron использует
   safeStorage; в Windows это системная защита DPAPI. В Core токен остаётся в памяти.
   При недоступном защищённом хранилище plaintext fallback отсутствует.
3. Нажмите «Подключить бота», дождитесь connected и откройте личный чат с ним.
4. Отправьте `/help`. Старые накопленные команды при подключении пропускаются:
   установка соединения не запускает старую задачу или старый apply.

Чтобы управлять агентом вдали от ПК, приложение и компьютер должны работать.
Используется исходящий long polling, входящий открытый порт не требуется. Бот с
активным webhook не сможет одновременно использовать getUpdates; настройте отдельного
бота либо отключите его webhook самостоятельно.

## Команды

| Команда | Действие |
| --- | --- |
| /status | Состояние задачи, основная модель, выбранный проект |
| /result | Последний сохранённый ответ текущего чата; полезно после переподключения |
| /resume | Продолжить checkpoint текущей приостановленной задачи, без повтора старого apply |
| /stop | Отмена активной задачи и ожидающего approval |
| /chat текст | Новая задача основной модели в отдельном Chat |
| /ide текст | Новая задача внутри уже выбранного на ПК проекта |
| /miya текст | Новая беседа с отдельной моделью Мии |
| /approval | Текущий путь, diff и точный approval ID |
| /approve ID | Apply только актуального approval/run |
| /reject ID | Reject только актуального approval/run |

Фильтр проверяет `from.id`, `chat.id` и private chat; посторонние пользователи,
группы, пересылки и via_bot команды игнорируются. Нельзя передать новый project_root
или произвольную команду shell через Telegram. Основной TaskService lock
сериализует локальный bridge и удалённые команды.

`TelegramService.observe` следует за передачей remote-задачи из Мии в основной
чат, поэтому итог большой модели возвращается тому же владельцу. Он ставит уведомления в ограниченную очередь, а polling worker
делает все сетевые вызовы. Ответы делятся по 3500 символов, общий предел 21000;
parse_mode не используется, link preview отключён, содержимое файлов не превращается в Telegram-разметку.
В /approval diff ограничен первыми 10000 символами; большой diff лучше просмотреть
полностью на ПК до apply. Номер подтверждения случайный и привязан к текущему run;
после Stop/перезапуска прежнее решение не применяется.

Token-bearing URL не возвращается в status и не включается в сообщения ошибок.
Локальная запись `telegram-secret.bin` шифруется Electron до записи; «Забыть токен»
удаляет только эту сохранённую запись. Подключение сохранённого бота запускается
явной кнопкой, а не автоматически при открытии настроек.

Файлы: [`telegram_service.py`](../core/python/telegram_service.py),
[`desktop_service.py`](../core/python/desktop_service.py),
[`ConnectionsSettings.tsx`](../apps/desktop/src/ConnectionsSettings.tsx).
Официальные протоколы: [Telegram Bot API](https://core.telegram.org/bots/api),
[long polling FAQ](https://core.telegram.org/bots/faq#how-do-i-get-updates).

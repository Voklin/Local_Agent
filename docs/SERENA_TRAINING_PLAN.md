# Пробный голос Мии: Serena → Piper

## Разрешение и критерий результата

24 октября 2026 пользователь начал автономное обучение до готовности пробной модели.
Источник тембра — выбранный пользователем Serena из Qwen 0.6B CustomVoice.
Нужно получить реальный обученный checkpoint, ONNX/JSON и записи новых фраз на CPU.
Сходство тембра и художественное качество после автоматической проверки оценивает пользователь.
Окончание процесса генерации или наличие базового checkpoint не означает готовую Serena.

## Где находится состояние

- Датасет и результат: `artifacts/voice-training/serena-v1/` (исключены Git).
- `manifest.json`: teacher, закреплённая revision, speaker, seed и хеш корпуса.
- `records.jsonl`: текст, время, SHA256 WAV, STT, similarity и accepted каждого примера.
- `status.json`: сколько записей создано/принято и длительность принятой речи.
- `pipeline-state.json`: стадия, PID worker, checkpoint, ошибка либо итоговая оценка.
- `.test-data/serena-corpus.log`: генерация; `.test-data/serena-pipeline.*.log`: контроллер.
- `training-6000.log`, `training-12000.log`, `export-*.log`: точные этапы в папке датасета.
- `training/lightning_logs/version_*/checkpoints/`: обученные checkpoints, `last.ckpt` для продолжения.
- `export/ru_RU-miya-serena-medium.onnx` и `.onnx.json`: кандидат для CPU.
- `export/evaluation.json`, `export/evaluation-*.wav`: четыре фразы вне обучающего корпуса.

Состояния: generating → training → exporting → trial_ready. Ошибка даёт failed;
недостаточная разборчивость после второй ступени — needs_review. Эти состояния
не должны сообщаться пользователю как готовая модель.

## Проверенные условия

RTX 5070 12 ГиБ; в начале свободно 10,7 ГиБ VRAM и около 43 ГиБ диска.
WSL отсутствует; установлены Visual Studio 18 BuildTools с C++.
Среда `build/voice-training/venv` создана отдельно. `.pth` подключает существующие
зависимости Qwen, включая `torch/torchaudio 2.11.0+cu128`; зависимости Piper training
установлены в новую среду, рабочая TTS среда не менялась. Piper 1.8.0, Lightning 2.6.6.

Исходники Piper закреплены на tag v1.8.0 (`639388b6317fc4731e91d53da42aea68fd4166ff`).
Cython `core.pyx` скомпилирован MSVC в Windows; `.pyd` установлен в training среду
в `piper/train/vits/monotonic_align/monotonic_align/`. Setuptools явно импортировался
перед setup.py, поскольку внешняя `.pth` не исполняет distutils startup hook.
Ошибка финального `--inplace` копирования не помешала сборке: проверенный бинарник
взят из `build/lib...`; CLI импорта и реальный шаг обучения затем прошли.

Официальный исходный checkpoint:
`rhasspy/piper-checkpoints/ru/ru_RU/irina/medium/epoch=4139-step=929464.ckpt`.
`prepare_checkpoint` загружает доверенный опубликованный Linux checkpoint с временной
совместимостью PosixPath/WindowsPath и сохраняет только state_dict, без оптимизатора.
Warmstart копирует 784 совпадающих параметра, пропусков нет. Карточка Irina указывает
Dataset License Unknown; происхождение базовых весов сохраняется, модель/датасет
не публикуются автоматически.

## Генерация и отбор

`generate_serena.py` использует подготовленные русские фразы и комбинации бытовых
ситуаций: 320 уникальных текстов. Это небольшой пробный корпус, не полноценный
профессиональный голосовой датасет. Teacher revision:
`85e237c12c027371202489a0ec509ded67b5e4b5`, Russian, Serena, CUDA BF16/SDPA, batch 2.
Каждый batch имеет фиксированный seed. Уже обработанные ID пропускаются при продолжении.
Manifest не позволяет незаметно сменить корпус или голос в той же папке.

Teacher WAV проверяется на конечные значения, mono и длительность 0,6–20 с,
передискретизируется из 24 кГц в PCM16 mono 22050 Гц. Локальный whisper.cpp
сравнивает текст после нормализации регистра/пунктуации/ё. Similarity ≥0,78
попадает в metadata.csv, остальные записи остаются в журнале как rejected.
После 12 записей доля accepted меньше 70% останавливает генерацию. Это грубый
автоматический отбор: STT может ошибаться и не подтверждает тембр/все ударения.
Первые 12 записей приняты, суммарно 49,2 с речи.

## Обучение, экспорт и контроль

`run_training.py --smoke` выполнил настоящий training/validation batch на GPU.
Основной запуск: batch 4, BF16 mixed, CPU threads 4, workers 0, validation 10%,
один дополнительный test example; seed 42. Learning rates G/D: 0,0001/0,00005.
Первая ступень ограничена 6000 global steps, при недостаточной ASR оценке —
продолжение из last.ckpt до 12000; также действует лимит 100 epochs.
Это global steps Lightning с двумя оптимизаторами, не число эпох или записей.
Сохраняются два лучших val_mel и последний checkpoint. MOS отключён вместе с
соответствующим callback, чтобы не скачивать дополнительную оценочную модель.

Training eSpeak получает данные из ASCII пути существующего Piper runtime:
нативная библиотека не открывает Cyrillic путь workspace и иначе пытается
использовать несуществующий D:/a путь сборочной машины. Обёртка задаёт factory
датасета с правильным data dir без изменения сторонних исходников.

`export_and_evaluate.py` использует штатный экспортёр с `dynamo=False`, поскольку
PyTorch 2.11 изменил exporter default. ONNX checker проверяет файл; затем Piper
на CPU синтезирует четыре held-out фразы. WAV должен быть PCM16 mono 0,5–30 с.
Средняя similarity STT должна быть ≥0,85, каждая ≥0,70. Если экспорт падает до
оценки, дополнительное обучение автоматически не запускается: сначала нужна починка.
Успешная ASR проверка означает trial_ready для прослушивания, а не доказанное
совпадение с Serena. Тест экспорта BASE-IRINA-NOT-SERENA отделён от обученного результата.

## Как продолжать без дублирования

1. Прочитать pipeline-state.json/status.json, проверить живой worker PID и журнал.
2. Пока PID жив и есть прогресс — не запускать второй generator/trainer.
3. При failed сначала прочитать конкретный log, исправить причину; принятые WAV
   не пересоздавать, готовый last.ckpt не терять. Сохранять границы 6000/12000 steps.
4. При trial_ready проверить ONNX/JSON/WAV и результаты, предоставить запись пользователю.
5. Контроль после завершения отключить. При needs_review не выдавать неразборчивый
   голос за готовый: проверить данные/промежуточные checkpoints и продолжить решение.

Работа полностью локальна, кроме скачивания публичных зависимостей и исходного
checkpoint. Обучение использует GPU последовательно после Qwen, действующий
пресет приложения не переключается на непрослушанную модель автоматически.

См. [официальное обучение Piper](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/TRAINING.md)
и [инструкцию скриптов](../tools/tts/training/README.md).

## Подтверждённый старт 24 октября

Первый реальный GPU training/validation batch завершился успешно. Отдельный
технический экспорт базовой Irina прошёл ONNX checker и четыре CPU/STT примера
(средняя similarity 0,955); это проверка инструментария, не обученная Serena.
Контроллер работает и ждёт завершения генерации. Heartbeat `serena-piper`
проверяет состояние каждые 15 минут, продолжает восстановление при сбоях и должен
быть отключён после проверки настоящего обученного результата.

## Переход к обучению

Корпус завершён: 320 из 320 WAV приняты автоматическим STT отбором,
1418,4 секунды речи (23 минуты 38 секунд). Запущена первая ступень VITS
до 6000 global steps; имеются обученные checkpoints, наблюдалась эпоха 10
с val_mel 0,4594. Это промежуточный результат, не готовая ONNX Serena.
Worker и training процесс живы; повторная генерация не требуется.

## Проверка финального сохранения и resume

После первой ступени Trainer завершился на 6000 global steps, но эпохальный
`last.ckpt` содержал только 5822: остановка посередине следующей эпохи не сохранила
последние обновления. Добавлен `SaveFinalCheckpoint.on_train_end`, сохраняющий
`training/final.ckpt`; pipeline предпочитает его эпохальному checkpoint.
Недостающие 178 шагов восстановлены из сохранённого состояния, WAV не пересоздаются.

Обнаружена особенность LightningCLI 2.6: при --ckpt_path он повторно подмешивает
hyper_parameters исходного запуска, включая одноразовый warmstart. Дополнительный
repair запуск с таким warmstart остановлен. `main.resume_fit_start` теперь
отключает оба warmstart перед on_fit_start и очищает их в сохраняемых hparams,
чтобы продолжение не сбрасывало веса к базовой Irina. Корректный resume не содержит
повторного сообщения о копировании 784 параметров из базового checkpoint.

## Итог: пробная модель готова

Проверен `training/final.ckpt`: 6000 global steps, сохранённый warmstart=null.
L2-разница embedding генератора относительно исходного checkpoint — 0,410705:
это действительно изменённые обучением веса, а не переименованная базовая Irina.
Контроль сохранён в `training-proof.json`. Экспорт final.ckpt прошёл ONNX checker.

ONNX: 63 516 051 байт, SHA256
`4610a755335a68bb102ea0bde426aa95f75191e8d6d438d8a51d99397319913d`.
Итоговая средняя similarity четырёх held-out текстов: 0,910, минимальная 0,773.
Эта величина — сходство распознанного текста, не оценка сходства голоса с Serena.
CPU генерация: 0,422 с для первого примера (5,608 с речи), 0,140–0,187 с для
остальных. Произношение несовершенно: STT ошибался на карандашах/тетрадях и части
фразы о дожде. Это пробный голос для оценки на слух, не подтверждённое качество
полноценного голоса. Автоматический критерий trial_ready выполнен.

Для пользователя подготовлена папка `artifacts/voice/serena-piper/` с ONNX/JSON
и `Start-Serena.cmd`/`Start-Serena.ps1` (UTF8 BOM для Windows PowerShell 5.1).
Скрипт запускает существующий CPU сервер с явным ModelPath; перед запуском порт
9080 должен быть свободен. Обычный Start-TTS не заменялся, модель автоматически
не активирована. Пример для сравнения с исходной Serena:
`artifacts/voice/miya-piper-serena-trained-ru.wav`.

Обучение и экспорт завершены, GPU освобождена. Модель/датасет остались локальными,
новых commits, публикаций, слияний или релизов этот этап не выполнял.
Heartbeat `serena-piper` удалён после проверки результата: автоматический контроль завершён.
